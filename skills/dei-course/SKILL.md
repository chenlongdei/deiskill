# dei-course 课程手册制作与发布

## 使命

一节 AI 办公实操课的全部交付：**创作**（学员手册、物料包、讲师卡）→ **发布**（推到用户常用的在线文档平台）。学员拿到就能照着做，讲师拿到就能上课。

## 铁律

1. **物料只用 Word / Excel**：学员物料一律 docx / xlsx（聊天记录、使用说明可以是 txt）。学员打不开 md，发现 md 物料先转换再往下走。
2. **数据闭环**：物料之间的数字互相对得上（会议记录说的数 = 数据表里的数）；演示用的乱数据用 Python 生成并校验合计，不手写；全部标注「虚构演示数据」。
3. **绝不编数**：手册里的耗时、成绩、课堂数字一律留空（____）或用讲师的真实记录。
4. **跨课伏笔**：上一节的「预估数」在下一节用真实数据揭晓；本节产出物是下节课的素材。
5. **同期不重复**：同一批学员的等待时间素材、企业案例按节分配，先列分配表再动笔。
6. **校对不过不发布**：数字核对、旧交叉引用、代码块围栏、中文校验一律 `grep -F`。
7. **发布平台跟着用户走**：用户设定的是哪个平台就发到哪个，没接好就停下说明，不换成别的平台。

## 流程

### Step 0 意图与位置

| 用户说的 | 走哪条线 | 读什么 |
| --- | --- | --- |
| 写第 N 节课手册、做物料包、出讲师卡、新课全套 | 创作线 | `references/handbook-writing.md`（八步 + 23 条踩坑）、`references/handbook-template.md`（13 章模板） |
| 推到飞书 / Notion / 钉钉、更新课程页、传附件 | 发布线 | `references/publish.md`，再按平台读 `publish-feishu.md`、`publish-notion.md` 或 `publish-dingtalk.md` |
| 做完顺手发出去、新课全套并发布 | 创作线 → 发布线 | 两边都读，中间必须过校对 |
| 物料转 Word/Excel、重新打包 zip | 物料工具 | `handbook-writing.md` 的 Step 4 + `scripts/pack_materials.py` |
| 只问课程结构或方法建议 | 直接回答 | 按需读，不进流程 |

用户只丢来一个课程方案、没说要做什么：按创作线走，先确认 `handbook-writing.md` Step 1 的四个决策。

**参考案例**：`examples/AI夜校四节课/` 是四节真实上过的课（Word 周报、Excel 乱数据、PPT、飞书办公系统），每节有主手册、讲师卡、Win/Mac 物料包，另有推到 Notion 后的 `发布记录.json`。写新手册前读一节对齐结构、语气和颗粒度；不要照抄它的场景和数字。

**课程文件夹**：用户指定了就用指定的；没指定就放 dei 工作区 `05_成品/课程/<课程名>/`。先运行 `python3 scripts/dei_workspace.py where` 确认工作区；报「还没有 dei 工作区」时，问用户放在哪里（给 2—3 个建议），确认后 `python3 scripts/dei_workspace.py init <路径>`；报「找不到」时说明哪个路径失效，不新建。Windows 上 `python3` 通常换成 `python`。

### 创作线（八步，细节见 handbook-writing.md）

读方案定位 → 设计虚构场景与数据闭环 → 写核心指令（三段标签）→ 物料包 → 写主手册（13 章）→ 三层钩子 → 课后练习 → 讲师卡与通读校对。

**确认点**：场景与人物设定、物料清单、手册目录，各给用户看一次再往下写。

物料打包：

```bash
python3 scripts/pack_materials.py <物料目录> <输出前缀> --root <解压后的根文件夹名> --structure <结构.json>
```

生成 `<前缀>-Win版.zip`（GBK 文件名，Windows 自带解压不乱码）和 `<前缀>-Mac版.zip`（UTF-8），并自动校验。Win 版是手工构造的 zip，不要改成用 Python zipfile 直接写。

创作线交付后，如果用户设定了发布平台（不是「只留本地」），问一句要不要发布。

### 发布线（细节见 publish.md）

1. `python3 scripts/dei_workspace.py publish` 读用户设定的平台和命令行状态；没设定时问一次并 `publish set <平台>`。
2. 平台是「只留本地」→ 交出本地路径，结束。
3. 读课程文件夹的 `发布记录.json`，判断新建还是更新。
4. 发布前确认：建几个页面、放在哪、带哪些附件。
5. 按平台的 reference 写页面、传附件、读回验证。
6. 写回 `发布记录.json`，记运行总账。

## 缺少信息时

- 没有课程方案：说明本 Skill 需要一份方案（每节课的主题、演示主线、只教到哪里），可以由用户口述，整理成 Markdown 后请用户确认。
- 方案缺发布平台、工具主线、物料形式、使用场景：一次问清，说明每一项会改变什么。
- 发布位置不明：问父页面、文件夹或知识库的链接，不默认放到根目录。

## 边界与停止条件

- 平台命令行没装、没登录、权限不足，或企业需要管理员授权：停下，说明缺什么、怎么补，不换平台、不反复重试。
- 校对有任何一项不过：不发布，列出问题。
- 附件上传失败：同一文件最多重试一次，仍失败就停下报告。

## 输出

```text
<课程文件夹>/                         默认 05_成品/课程/<课程名>/
├── 第N节课手册｜<本节钩子标题>.md     学员版主手册（13 章）
├── 讲师练习卡｜第N节练习.md           内部资料，默认不发布
├── 物料包/
│   ├── <场景>-<主题>物料包-Win版.zip
│   ├── <场景>-<主题>物料包-Mac版.zip
│   └── 源文件/                        改版时重新打包用
└── 发布记录.json                      发布到哪里、页面链接和 ID
```

给用户：各文件的绝对路径；发布了的话，每个页面的链接。运行结束用 `python3 scripts/dei_workspace.py log dei-course <创作|发布> <ok|partial|failed> <产出路径>` 记总账。

## 禁止事项

- 不在手册里编造数字、案例出处或学员成绩。
- 不把讲师练习卡发到学员能看到的位置。
- 不开公开分享链接，除非用户明确要求。
- 不打印或保存平台令牌；`发布记录.json` 里只有链接和 ID。

完成当前任务后直接结束。用户的请求超出本 Skill 范围，或询问下一步时，用一句话说明还需要哪种能力，不点名其他 Skill；当前环境已经安装 `dei` 时，补一句「可以用 `$dei` 继续」。

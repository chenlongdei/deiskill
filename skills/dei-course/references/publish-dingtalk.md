# 发布到钉钉

> 发布平台是钉钉时加载。先读 `publish.md`（确认点、发布记录、校对）。
> 本流程尚未在真实钉钉组织里实测，第一次使用时边走边核对命令。

## 通道

- **钉钉官方命令行 `dws`**（DingTalk Workspace CLI，开源仓库 `DingTalk-Real-AI/dingtalk-workspace-cli`，Apache-2.0）。覆盖文档、AI 表格、群聊、待办等，面向 Agent 设计，返回结构化 JSON。
- 安装方式按官方仓库 README，装好后 `dws --help` 能运行。
- 访问企业数据需要**组织管理员授权**；报未授权时停下，告诉用户请管理员开通，不换平台。
- 当前 Agent 已接好钉钉连接器时也可以用连接器，规则相同。

## 第 0 步：查清命令

不凭记忆写命令：

1. `dws --help` 找到文档（知识库 / 文档）相关的模块；`dws <模块> --help` 看新建、更新、上传附件的子命令。
2. 如果 `dws` 自带给 Agent 的说明（内置 Skills 或指南），先读它。
3. 每个写操作先加 `--dry-run` 看请求，确认后再真正执行；输出用 `-f json` 方便取链接和 ID。

## 第 1 步：新建文档

- 先问清放在哪个知识库或文件夹。
- 正文按 `publish.md` 第 5 节转换；钉钉文档不支持的块退回成引用块或普通段落。
- 如果 `dws` 只能建空文档、不能整篇写 Markdown，就先建文档再分段写入；仍然不行，就上传 docx 版手册作为替代，并告诉用户排版会弱一些。

## 第 2 步：附件

物料包 Win 版、Mac 版各上传一份，放在文档顶部的下载说明之后。找不到「插入附件」的命令时，上传到同一文件夹，再在文档里写明文件位置。

## 第 3 步：更新与验证

- 更新前读 `发布记录.json` 拿文档 ID，读回当前内容再改。
- 写完读回文档，核对附件和顺序，把链接写进 `发布记录.json`。
- 第一次走通后，把实际用到的命令补进本文件，替换上面的「查清命令」步骤。

# 发布：通用规则（所有平台）

> 发布线 Step 0 读本文件，再按平台读 `publish-feishu.md`、`publish-notion.md` 或 `publish-dingtalk.md`。

## 1. 先确定平台

用户平时用哪个在线工具分享文档，是 deiskill 的共用设置，记在 `~/.deiskill/config.json` 的 `publish_platform`（安装 deiskill 时问过一次）。

```bash
python3 scripts/dei_workspace.py publish            # 看当前平台、命令行装没装
python3 scripts/dei_workspace.py publish set feishu # 改成 feishu / notion / dingtalk / local
```

- 返回 `"platform": ""`（还没设）：问用户一次——「你平时用哪个在线工具分享文档：飞书、Notion、钉钉，还是只留本地？」——用 `publish set` 记下，以后不再问。
- `local`：不发布，把本地文件路径交给用户，结束。
- 用户这次点名了别的平台（例如设置是飞书，但这次说「推到 Notion」）：按这次说的做，不改设置；用户说「以后都用 X」才 `publish set`。

## 2. 没接好怎么办

`publish` 返回的 `ready` 为 false 时，说明缺什么，给出返回里的 `install` 和 `login` 提示，用户同意后再安装；登录要用户自己在终端完成（扫码或浏览器授权）。

- 当前 Agent 已经接好同一平台的连接器（工具名里带 notion、lark、feishu、dingtalk 的），可以直接用连接器，不必装命令行。
- **不改用别的平台**：用户选的是钉钉而钉钉没接好，就停在这里，不悄悄推到飞书。
- 钉钉、飞书的企业数据可能要管理员授权；报权限不足时停下，告诉用户需要谁开什么权限。

## 3. 发布前的确认点

一次说清，等用户点头再写：

1. 建几个页面（每节手册一页；讲师练习卡是内部资料，默认**不发布**，用户要求才发且单独放）。
2. 放在哪：父页面、文件夹、知识库或数据库。课程文件夹里有 `发布记录.json` 就沿用上次的位置；没有就问用户要链接。
3. 带哪些附件：物料包 Win 版和 Mac 版各一份。
4. 是新建还是更新已有页面，更新的话是改几处还是整页重写。

不开启公开分享和「互联网上获得链接的人可查看」，用户明确要求才开。

## 4. 发布前必须过的校对

和创作线最后一步相同，有一项不过就不发布：

- 数字前后一致（手册里的数 = 物料里的数），用 `grep -F` 核对，不靠眼看；
- 没有指向旧章节号、旧文件名的交叉引用；
- 指令代码块的围栏成对；
- 物料是 docx / xlsx / txt，没有 md；两个 zip 都通过 `pack_materials.py` 的校验。

## 5. 通用排版原则（各平台都适用）

- 页面顶部依次是：附件下载区（注明「选你的系统版本」）→ 两个附件 → 分隔线 → 一句话导语 → 正文。
- 块与块之间空一行；正文不手动折行。
- 指令、提示词放进代码块，学员一键复制。
- 正文里提到文件名一律包成行内代码，防止被平台自动识别成链接。
- 本地锚点、「返回目录」链接删掉，平台自带目录。
- 平台不支持的块（例如某种彩色提示块）退回成引用块，不硬造语法。

## 6. 发布记录

每门课的课程文件夹里放一份 `发布记录.json`，记录推到了哪里，下次更新直接读它：

```json
{
  "platform": "feishu",
  "parent": "父页面或文件夹的链接",
  "lessons": {
    "第1节": {
      "title": "页面标题",
      "url": "页面链接",
      "id": "平台里的页面或文档 ID",
      "icon": "📄",
      "attachments": ["…-Win版.zip", "…-Mac版.zip"],
      "updated_at": "2026-11-13T10:58:00+08:00"
    }
  }
}
```

- 参考案例：`examples/AI夜校四节课/发布记录.json`（四节课推到同一个 Notion 数据库，含页面 ID、icon、附件）。第一次给一门课建发布记录时照它的结构写。
- 同一门课换了平台（以前推 Notion，现在推飞书），在 `lessons` 里按平台另记一份，不覆盖旧的。
- 记录里只有链接和 ID，不放令牌。
- 发布完运行 `python3 scripts/dei_workspace.py log dei-course 发布 ok <发布记录.json 路径>`。

## 7. 收尾验证

重新读回页面顶部：附件在、顺序对、没有重复块、正文没有被自动链接化的文件名。然后把每个页面的链接交给用户。

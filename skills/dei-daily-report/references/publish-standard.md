# 对外日报：内容方法与标准

各模块的分析报告是研究底稿，写给自己看；对外日报是成品，写给公开读者看。成品从底稿里取材，但目的不同：**找出今天最重要的事，把它想清楚、说清楚，让普通读者愿意读完、也读得懂。** 它不是信息汇编，也不展示我们怎么做出来的。

研究方法沿用各模块的 `analysis-method.md` 与 AI 模块的 `plain-explanation.md`（假设驱动、边际变化、由表及里、通俗说理），本文只规定成品怎么取舍、怎么写、怎么检查。

## 1. 结构：五个模块，条目取单数

| 模块 | 条目 | 写什么 |
|---|---|---|
| 今天最重要的一件事 | 1 | 全天唯一的头条，讲透 |
| 国家政策 | 3 或 5 | 前几条是重点，最后一条是「其他值得知道的」合集 |
| AI | 3 或 5 | 同上 |
| 社会热点 | 3 | 商业 / 女性情感 / 本周持续在讨论的话题 |
| 接下来值得关注 | 1 张表 | 时间 + 事项 |

最后附「主要资料来源」。模块内用 `###` 编号小标题，条目数必须是单数；重点条目不超过 4 条，宁缺毋滥。

## 2. 篇幅与取舍

正文 5000—8000 字（不算资料来源、Markdown 符号和链接）。超了先删，删的顺序：

1. 和头条重复的背景、铺垫。
2. 只有标题没有机制的消息（只能复述"某某发布了某某"）。
3. 常规外事、会议、宣传类报道。
4. 同一主题的第二个例子。

不删的：改变了某类人决策的事实、关键数字和它的口径、"和以前比变了什么"、成立条件。篇幅不够时，把重点条目里的细节和数字补回来，不去凑新条目。

## 3. 今天最重要的一件事

### 怎么选

按顺序问，第一个答"是"的就是头条：

1. 有没有一件事**改变了一大类人接下来的决策**（企业怎么用人、个人怎么学、钱往哪里投），而且有官方原文或可靠来源支撑？
2. 有没有几份文件或几条消息构成**明确的承接关系**（前一份定方向，后一份落实）？只有原文能证明承接才算，同主题不等于承接。
3. 有没有一个**反直觉的事实**，能解释一个大家关心的现象（例如"模型为什么一直降价"）？
4. 都没有时，取政策模块评级最高的一条，或 AI 模块影响面最大的一条，单独讲透，不强行串联。

重复报道、单日热搜、没有原文的传闻不当头条。

### 怎么写

一个 `###` 小标题，用问句或判断句，不加句号。正文按这个顺序，每段一个意思，段首加粗点题：

1. **第一句直接给答案。** 先抛出问题，紧接着给出一句话的答案。不要用"单看今天的新闻……"之类的铺垫。
2. **发生了什么。** 谁、在哪天、做了什么，关键条款或数字。多份文件时按时间分步写。
3. **和以前比，变了什么。** 找到前序文件或上一次的同口径数据，说清增量。重复报道要写明。
4. **为什么是这样。** 讲机制：谁的约束、谁的成本、谁的风险。
5. **也可能不会这么顺利。** 写最有力的相反情况（替代方案、门槛、时滞）。
6. **会影响谁。** 2—4 类人，每类一句话说清他们要面对什么。
7. **接下来看什么。** 能验证或推翻这个判断的下一个节点。

### 封面那一句话

从头条提炼一句**判断**，不是清单，不罗列三件事，不加句号；8—18 字，最多分两行，在自然停顿处断开（例："AI 先替代谁 / 国家排好了顺序"）。

## 4. 国家政策

- 重点条目写：事实（主体、动作、数字、生效时间）→ 这组事实对谁意味着什么（国内一侧、海外一侧等）→ 成立条件。
- 运行数据不是政策，写明口径；不同口径的数字不能相加或比倍数，多组数据并列时用表格并注明。
- 「其他值得知道的」每条一行：加粗关键词 + 一句事实 + 必要时半句含义。一周内的其他要闻也并入这里。
- 「近 7 天变化」不单独成节：有延续的写进对应条目，构成主线的写进头条。

## 5. AI

- 重点条目优先选：改变成本或做法的实测、改变竞争规则的趋势、影响行业的资本和合同、连续发生的同类事故。
- 术语首次出现立即用一句白话解释（"MCP 是让 AI 调用外部工具的通用接口"）。
- 实验和厂商数据写明是谁做的、测了什么、边界在哪；用表格放关键数字。
- 一周内的同类事件用时间表排出来，再写共同点。
- 只有一家来源、或来源之间数字冲突的，写成"各家报道不一"或不写具体数字，不在成品里讨论核实过程。

## 6. 社会热点

只写三类，各一条：

1. **商业**：选一个讲透（事实 → 讨论的共识与分歧 → 容易被误读的地方 → 机制），其余列为"另外几条商业话题"，每条一句话。
2. **女性情感**：亲密关系、婚育、家庭与育儿、职场女性、身材与容貌焦虑等。写法：事实 → 回答里的主要观点（标明是"有人认为"）→ 背后共同的压力。**当天热榜没有合适题目时**，从近 7 天热搜或热榜里取仍在讨论的女性话题，并写明时间；仍然没有，就用一条商业话题补位，不硬凑。
3. **本周持续在讨论的话题**：四列表格。

| 话题 | 怎么开始的 | 一周进展 | 最新状态 |
|---|---|---|---|
| 名字 | 日期 + 起因 | 关键词加箭头：A → B → C | 最新一步 + 今天是否仍在热榜 |

表后可补一两句解释。最新状态必须有一个可靠来源支撑；只有热搜词、查不到报道的，不写具体情节。

流量类话题（直播施压、网红骂战等）不单独写；确有商业或女性情感含义的，放进对应类别。

所有社会热点都要区分三种东西：事实、回答者的观点（"有回答指出"）、传闻（"未经证实"）。不把多人重复的猜测升级为事实。

## 7. 客观与边界

- 只写事实、机制和条件，不写"我们建议"、"对你来说"、课程素材、商机待验证等自用内容。
- 判断要有来由：数据、原文或明确的因果链；推断要说"可能"、"取决于"。
- 来源写在文末「主要资料来源」，正文需要时就近写"据某某报道"。
- 日期写具体日期，不写"昨天"、"本周三"。

## 8. 不进成品、单独告诉用户的

以下内容在交付时用一段话告诉用户，不写进成品：模块未完成或未配置、原文未取得、来源冲突的细节、哪些事实只取得了转载、回答只读了摘要、本期因缺素材做的补位。

## 9. 换了题材时怎么办

| 情况 | 做法 |
|---|---|
| 当天没有能串起来的多份文件 | 按 §3 第 3、4 步选头条，单独讲透一件事，不强行串联 |
| 政策当天只有常规报道 | 政策模块写 3 条：1 条重点（可用近 7 天里仍在推进的事项，写明日期）+ 1 条数据 + 其他合集 |
| AI 当天很平淡 | AI 写 3 条；重点选影响最大的产品动作或实测，不用热度凑 |
| 遇到重大突发（灾害、重大人事、市场剧烈波动） | 可成为头条；只写已证实的部分，事态未明的写"目前已知" |
| 没有可用的数字 | 速览卡片用列表，不做统计图；长文不为了好看造表 |
| 女性情感当天没有题 | 见 §6 第 2 条 |
| 某模块整体缺失 | 成品照常出，缺的模块不写，篇幅向其他模块倾斜；缺失原因单独告诉用户 |

## 10. 自检

先跑 `publish/check_report.py <文字版.md> <data.json>`，它会检查字数、模块、单数条目、四列表格、内部用语和封面标题。再逐条人工问：

1. 读者看完头条，能不能用一句话复述"发生了什么、为什么重要"？
2. 每个重点条目，有没有"和以前比变了什么"或"影响谁"？
3. 有没有哪句话需要先懂术语才能看懂？
4. 有没有哪个判断找不到来由？
5. 每个数字的口径和日期写清了吗？
6. 有没有把回答者的猜测写成了事实？

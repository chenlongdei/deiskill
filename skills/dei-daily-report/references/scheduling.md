# 统一调度

仅在用户请求实际创建或调整定时时使用。Skill 文件本身不会注册定时器；定时只能由用户正在使用的 Agent 或系统调度器触发。先确认用户用的是哪个 Agent，不假设。

## 选择调度方式

| 用户环境 | 方式 | 注意 |
| --- | --- | --- |
| Claude Code（本机） | macOS 用 launchd、Linux 用 cron、Windows 用「任务计划程序」（`schtasks /Create`），定时运行 `claude -p` 并传入下方提示；或在 macOS 上用 policy 模块的 `bash install.sh --launchd` | 电脑需开机联网，`claude` 已登录；保存位置在外接盘或云盘时需确保已挂载 |
| Claude Code 云端定时（/schedule） | 只适合不依赖本机文件的任务 | 云端读不到本机的 config.json、数据目录和凭证，日报一般不适用 |
| 其他 Agent（Codex、WorkBuddy 等） | 使用该 Agent 自带的定时功能 | 按该 Agent 文档，先列出已有任务，优先更新避免重复 |

只开一套调度。替换旧调度时记录原配置，仅迁移用户明确涵盖的渠道；范围不清楚时先确认，不擅自停用旧任务。子模块里的首次引导、频率建议和历史预约文字不等于授权创建第二套调度。

## 时间与时区

日报按北京时间（Asia/Shanghai）计算。系统调度器按**本机时区**触发：创建前先读取本机时区，把用户要求的北京时间换算成本机时间，并在说明中写出换算结果（例如本机为 UTC−6 时，北京时间 05:00 对应前一日 15:00）。policy 的 `install.sh --launchd` 要求本机时区为北京时间，否则改用上表其他方式。

完成、失败、部分完成或需处理时通知；重复检查无变化且无可行动事项时保持安静。保留用户的静音偏好。

## 综合晨报提示

> 使用 dei-daily-report（入口 <本 Skill 安装目录>/SKILL.md）生成全平台日报，选择 policy、ai、zhihu、douyin，使用各模块默认窗口并按 history_days 回补。完整执行选中模块，保存综合稿与运行记录，附子产物链接。单模块失败继续其它模块，明确部分完成及缺口。缺少配置时标 unsupported，不要提问。不要创建或修改调度。

## 按领域提示

> 使用 dei-daily-report（入口 <本 Skill 安装目录>/SKILL.md），只执行 ai、policy，使用默认窗口并按 history_days 回补。保存统一入口稿、运行记录和子报告链接，明确覆盖与完成状态。不要运行其它模块或更改调度。

保存提示时把 `<本 Skill 安装目录>` 换成实际绝对路径。不把私人任务 ID 写入可分享的 Skill。

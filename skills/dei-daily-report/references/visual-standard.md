# 对外日报：视觉呈现与数据格式

同一期内容出两种形式，**定位不同，内容不能一样**：

| 形式 | 给谁 | 目的 | 尺寸 |
|---|---|---|---|
| 速览图卡 | 公域里还不认识你的人 | 引流：让人看到这一期的信息量，光看图也能学到东西，认可专业价值，愿意进一步了解 | 3:4，2160×2880，封面 + 10 张左右 |
| 深度长文 | 社群成员 | 深度：每条的来龙去脉、和以前比变了什么、为什么、影响谁、相反情况 | 手机阅读宽度，导出 1080 宽 |

**图卡讲"是什么、意味着什么"，长文讲"为什么、和以前比、会怎样"。** 图卡覆盖每个模块的多条内容，每条用一两句话讲清事实和含义；只有头条在图卡里给出一份深度解读作为示范（两张），其余模块的深度分析留在长文。最后一张卡片引导去社群看完整版。

视觉语言借鉴杂志封面：一期一个强色 + 墨黑 + 新闻纸底色；衬线大标题；细线分栏；大号编号。颜色按星期轮换（周一红、周二橙、周三黄、周四蓝、周五绿、周六粉、周日薄荷），也可在 data.json 的 `theme` 指定。

## 期号

第一次对外发布为第 001 期，之后每个新的报告日加 1，同一天重跑沿用同一期号。用 `publish/issue.py <output_root> <YYYY-MM-DD>` 取号，记录在 `<output_root>/对外日报期号.json`。不要用日期当期号。

## 封面规则

- 报头：品牌名 + 竖排"日报"、期号、日期、全文字数和阅读时间。
- 大标题：头条提炼出的一句判断，不是清单，不加句号，最多两行（见 publish-standard §3）。
- 本期目录：国家政策、AI、社会热点三栏，每栏 3—4 条具体条目，合计 8 条以上。目录就是封面上的"信息量"，条目要写出具体的事（"新能源车占国内新车销量 64.3%"），不写空泛的类别。
- 底部：本期条数和"向后滑动"。
- **封面上出现过的内容不在封面上重复；头条卡片的标题不能和封面大标题相同**，头条卡片从封面的判断往下讲（例如封面"AI 先替代谁 国家排好了顺序"，卡片"一个月三份文件 是同一条主线"）。

## 速览卡片

每张卡片：顶栏（品牌、期号、页码）→ 版块标签 → 一句标题 → 内容块 → 页脚。标题是一句结论，不是版块名；两行标题用 `\n` 在自然停顿处断开。

默认顺序（约 12 张，按当天内容增减）：

| 卡片 | 内容 |
|---|---|
| 01 封面 | 一句判断 + 本期目录 |
| 02—03 今天最重要的一件事 | 深度示范：来龙去脉（时间线）→ 影响谁、接下来看什么 |
| 国家政策 × 2 | 重点条目（数字 + 国内/海外等含义）；其他值得知道的（每条一句事实 + 半句含义） |
| AI × 3—4 | 每个重点条目一张：数字或对比 + 两三句"这意味着什么"；其他消息并入相关卡片 |
| 社会热点 × 3 | 商业（一条讲清 + 其余一句话）、女性情感、本周持续（三列表） |
| 最后一张 | 接下来值得关注 + 引导去社群看完整版 |

| 内容块 | 何时用 |
|---|---|
| `steps` 竖排时间线 | 头条有先后步骤 |
| `lead` 一句话总结 | 一张卡片的收尾判断 |
| `points` 小标题 + 一两句解释 | 讲清一条消息或一类人受到的影响；图卡的主力 |
| `stats` 三个大数字 | 当天有 3 个口径清楚、值得记住的数字 |
| `bars` 柱状对比 | 同一口径下的几项对比，差距本身就是信息 |
| `note` 说明条 | 口径提醒或一句"这意味着" |
| `list` 关键词 + 一句话 | 其他消息合集；没有数字时的默认选择 |
| `table` 三列小表 | 本周持续话题（话题 / 一周进展 / 最新状态） |
| `agenda` 日程 | 时间线上的多个事件、接下来值得关注 |
| `cta` 引导 | 最后一张卡片 |

没有合适数字时不做 `stats` 和 `bars`。一张卡片 2—3 个内容块；正文字号不小于 26px（导出后在手机上清晰），放不下就拆成两张，不缩字号。

## 深度长文

由文字版 Markdown 直接排版，不改内容：

- 报头：品牌、日期、头条一句话、说明、**目录**。目录每项写模块名 + 当天重点（`toc`），并估算阅读分钟数。
- 每个 `##` 是一个版块，自动编号 00、01……；"今天最重要的一件事"用深色底。
- `###` 是条目标题；`**加粗**` 显示为划线重点，每段开头的点题句和关键结论加粗，不要整段加粗。
- 表格、列表、链接都按原文渲染；资料来源排在最后，字号缩小。

## data.json

```json
{
  "brand": "品牌名，来自 config.json 的 publish_brand",
  "community": "完整版所在的社群名，来自 config.json 的 publish_community",
  "issue": 1,
  "date": "2026 年 11 月 12 日",
  "weekday": "星期四",
  "theme": "auto 或 red/orange/yellow/blue/green/pink/mint",
  "read": "全文约 5000 字 · 12 分钟读完",
  "article": "文字版 Markdown，相对本文件的路径",
  "headline": ["第一行", "第二行"],
  "contents": [{"k": "国家政策", "items": ["具体条目", "…"]}, {"k": "AI", "items": []}, {"k": "社会热点", "items": []}],
  "toc": ["每个编号模块的当天重点，按顺序，与长文模块一一对应"],
  "cards": [
    {"id": "core", "dark": true, "kicker": "版块标签", "title": "一句结论",
     "blocks": [{"type": "steps", "items": [{"d": "", "h": "", "t": ""}]}, {"type": "lead", "t": ""}]}
  ]
}
```

各内容块字段：`points.items` 为 `{h, t}`；`table` 为 `{head: [], rows: [[]]}`；`stats.items` 为 `[数字, 说明, 口径]`；`bars` 为 `{unit, items: [[名称, 数值]], callout}`；`list.items` 为 `[关键词, 一句话]`；`groups.items` 为 `{h, s, items: []}`；`agenda.items` 为 `[时间, 事项]`；`cta` 为 `{t, s}`。完整示例见 `publish/example/data.json`。

## 渲染

```bash
python3 publish/check_report.py <文字版.md> <data.json>
python3 publish/render.py <data.json> --out <输出目录>
```

输出目录放在 `output_root` 下当天的运行目录里，不放进 Skill 安装目录。渲染需要 playwright 和联网加载字体；没有本机 Chrome 时自动改用 playwright 自带的 Chromium。网页内导出会丢字体，所以图片统一由 render.py 生成。

# 抖音博主监控（日报模块）

## 分工

本模块**不抓取、不转写、不调用任何计费接口**。抖音数据由已安装的内容采集能力负责：在各 Skill 的 `metadata.dei-handoff` 里找能「接手抖音监控工作簿 → 交出更新后的工作簿副本和失败清单」的那一个，按它的说明更新工作簿。本模块从更新后的工作簿接手。

没有安装这种采集能力，或它停在凭证、余额问题上时：本模块标 `unsupported` 或 `failed`，写明缺什么，不自己去抓。

## 输入

- 工作簿：总入口 `config.json` 的 `douyin_default_input`；用户本次指定的文件优先。不随意挑候选工作簿。
- 更新结果：采集能力直接更新这份工作簿（更新前自动备份到工作区 `99_系统/备份/抖音监控工作簿/`），失败清单是工作区 `99_系统/日志/抖音监控工作簿/` 里本次运行的 `.report.json`（采集能力运行结束时会打印它的路径）。只用本次运行的记录，不把上次的当成这次的结果。

## 流程

1. 确认输入工作簿存在，然后请采集能力按滚动近 7 天更新它（零发布账号补最近 7 条）。
2. 读更新后的工作簿：每个博主一页，取本次窗口内的新视频（按发布时间）和已有视频的最新数据。
3. 读 `.report.json` 的失败清单，原样列进缺口。
4. 写客观更新摘要（见下）。

## 摘要写什么

- 窗口和覆盖：实际时间窗口、成功的博主数、失败的博主和原因。
- 每个博主：窗口内新发了几条；每条的标题、发布时间、点赞、评论、收藏、转发、赞粉比；逐字稿只引前 5 秒和结尾。
- 全部博主中数据最高的 3—5 条（按点赞或赞粉比，写明口径）。

只写客观数据。不做分类、内容逻辑、钩子类型等主观拆解，除非用户另行要求。缺失的数据写「缺失」，不写成 0；24 小时、7 天、30 天的增量没有历史快照时留空，不用当前快照冒充。

## 停止条件

- 工作簿不存在或打不开：停下来问用户（没有工作簿时，可以让采集能力从模板生成一份），不在磁盘上搜索候选文件。
- 采集能力报告凭证无效或余额不足：本模块标 failed，说明原因，其他模块照常完成。

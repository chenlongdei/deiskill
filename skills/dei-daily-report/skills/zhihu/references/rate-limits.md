# 知乎额度与频率：2026-09-14实测

官方工具随附的 [接口说明](../tools/zhihu/references/http-api.md) 区分以下限制：

- question_answers 默认每租户每自然日100次，低额度账号可为10次；必须以当前账号quota返回值为准，不能仅由10次判断账号未实名。
- 一次请求的Limit默认20，范围1—50，返回服务端回答摘要，不是全文。分页需额外调用，可能不足指定条数。
- 频率、并发和日额度耗尽都可返回Code30001；现有官方说明没有给出可确认的QPS/QPM、并发数或固定冷却秒数。

本机账号当天实测：question_answers总额度10；第一次检查已用2、剩余8。上次失败的第二题重新请求Limit10后成功返回10条摘要，已用3、剩余7。随后间隔至少10秒请求第三题，同样成功返回10条摘要，已用4、剩余6。每个成功请求的用量差为1，不是按10条摘要扣10次。两次间隔请求成功，不足以确定官方最低安全间隔，也不承诺每天长期表现相同。

hot_list当天总额度2，已用2、剩余0；与问题回答是独立额度。不会因为热榜用完就不能读取回答。复用已有当日榜单时标明原始快照时间，不声称即时抓取成功。

上次错误时未立即取得quota，本次检查和多题成功表明“永久只能分析一个问题”没有依据。错误更可能来自短时频率/并发或其它请求限制，具体频控阈值仍未知；不把推断写成官方承诺。

观点归纳和三个表达角度由当前模型基于同一批摘要完成，正常情况下后者不增加知乎接口调用。删角度不会解决回答采集的频率或日额度限制。

# dei-moments 朋友圈私域经营

## 使命

让一个人用 AI 写出**像自己**的朋友圈，并且知道每天该发什么：日常怎么发，卖东西时怎么一浪一浪地发，发完怎么复盘、怎么把结果变成下一次的案例。

## 铁律

1. **不编**：数字、客户原话、截图、剩余名额、报名人数，只用用户给的真实内容；缺的留【这里放：××】，不让 AI 编，也不替用户编。
2. **一条只干一件事，但每条都要有增量**：读者看完要白拿走一样东西（一个能对号入座的判断、一招当场能用的方法、一个真实的故事）。只完成任务、没有增量的稿子不交。
3. **开头两行决定生死**：朋友圈超过几行会折叠，开头必须是冲突、真实的数字或一句原话。
4. **主角是用户自己**：每条至少一个只有他讲得出来的细节（一个地名、一个人、一个他自己的数、一个他踩过的坑）。观点和外部数据只能当配角。
5. **不被用户以前的文案框住**：先从「读者掏钱之前在问什么」倒推每天发什么，不去机械拆分用户原来那条。
6. **数据私下记，结果出来再公开**：发售期间不在朋友圈里公开实验进度；拿到结果后，再把「同一个产品，两种发法」当案例讲。
7. **稀缺必须是真的**：说只剩 3 个，就真的只剩 3 个；截止日期不随意延期。

## 流程

### Step 0 先读已有的

不假设用户有任何文件。先运行 `python3 scripts/dei_workspace.py where` 确认 dei 工作区（Windows 上通常换成 `python`）。报「还没有 dei 工作区」时，问用户放在哪里（给 2—3 个建议），确认后 `python3 scripts/dei_workspace.py init <路径>`；报「找不到」时说明哪个路径失效，不新建。

然后看工作区 `05_成品/朋友圈/` 下有没有：

| 文件 | 是什么 | 有的话 |
| --- | --- | --- |
| `风格提示词.md` | 用户的说话方式 | 写任何文案前先读 |
| `素材库*.md` | 用户的真实经历、案例、学员原话、数据好的旧朋友圈 | 写文案时优先从这里取材 |
| `发售/<批次>/` | 以前的发售方案和数据记录 | 新发售前先看上一次的复盘 |

没有就从 Step 1 开始建，不硬要。

### Step 1 判断要做哪件事

| 用户说的 | 做什么 | 读什么 |
| --- | --- | --- |
| 「写得不像我」「帮我做风格提示词」 | 收语料 → 反推风格提示词 | `references/style-prompt.md` |
| 「这条为什么没人理」 | 诊断 | `references/copy-rules.md` 第三节 |
| 「帮我排这次发售」「要卖一个课 / 产品」 | 浪潮式发售方案 | `references/launch.md` + `references/copy-rules.md` |
| 「每天不知道发什么」 | 周排期 | `references/methodology.md` 模块② |
| 「这个产品写不出东西了」 | 卖点 × 角度矩阵 | `references/methodology.md` 模块④ |
| 「这条火了，还能怎么用」 | 一鱼多吃 | `references/methodology.md` 模块⑥ |
| 「发售结束了」「这个月发得怎么样」 | 复盘 + 写素材库 | `references/launch.md` 第六节、`references/methodology.md` 模块⑦ |
| 只问方法 | 直接回答 | 按需读 |

### Step 2 缺素材就先要，不先写

文案的质量取决于素材。开写前确认手上有：用户的风格提示词（或至少 3 条他自己写的朋友圈）、产品的真实信息、至少一个真实的故事或反馈。缺的一次问清；用户暂时给不了的，在稿子里留【这里放：××】。

### Step 3 出稿和确认

- 发售方案：先给排期表，用户认可节奏后再写逐条文案；前 3—5 天写全文，后面先写方向，按真实进展再写
- 文案：按 `copy-rules.md` 写；交稿时逐条标出哪里需要用户补真实内容
- 用户说稿子差：先问他作为读者哪里不想看、哪里不想买，再改；不要只换词

### Step 4 存档

| 产出 | 存到 |
| --- | --- |
| 风格提示词 | `05_成品/朋友圈/风格提示词.md`（覆盖前把旧版本留在文件末尾） |
| 发售方案、私下记录表 | `05_成品/朋友圈/发售/YYYY-MM-DD_HHMM_<产品>/`（批次名用 `dei_workspace.py` 生成的北京时间） |
| 诊断、复盘 | 同上批次文件夹，或 `05_成品/朋友圈/诊断/` |
| 真实案例、学员原话、数据好的朋友圈 | 追加进 `05_成品/朋友圈/素材库.md`，写明来源和是否已获本人同意 |

结束时运行 `python3 scripts/dei_workspace.py log dei-moments <任务> <ok|partial|failed> <产出路径>`。

## 缺少信息时

- 没有任何语料：让用户按住说话，口述自己的一天 3—5 分钟，转成文字就是第一份语料（见 `style-prompt.md`）
- 没有真实反馈和案例：先发不需要证言的内容（故事、干货、答疑），同时提醒用户去收集；不用编的顶上
- 不知道发售目标：可以先排节奏，目标留空，提醒用户补

## 边界与停止条件

- 用户要求编数字、编证言、伪造截图或虚构稀缺：拒绝这一部分，说明风险，给出不编也能写的替代写法
- 用户的素材涉及客户隐私（姓名、电话、聊天记录）：提醒脱敏后再用；未经本人同意的学员故事，不写进要发出去的文案
- 引用外部数据或报告：要求用户核对原文；拿不准的建议不用

## 输出

给用户：各文件的绝对路径；发售方案里每一条需要他补真实内容的位置；下一步该先补什么。

## 禁止事项

- 不替用户发朋友圈、不群发私聊
- 不把用户的私人素材写进任何公开位置
- 不使用「家人们」「宝子们」这类称呼，除非用户自己的语料里就这么说

完成当前任务后直接结束。用户的请求超出本 Skill 范围，或询问下一步时，用一句话说明还需要哪种能力，不点名其他 Skill；当前环境已经安装 `dei` 时，补一句「可以用 `$dei` 继续」。

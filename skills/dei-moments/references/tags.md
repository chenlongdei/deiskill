# 私域标签：先分清给谁看，再写发什么

> 用户要规划标签、问「这条朋友圈该给谁看」时读；排发售、写私聊、复盘时，按 SKILL.md 的要求读对应的小节。
> 用户自己的标签体系存在 `<moments>/标签体系.md`；这份文件只讲方法，**不替用户定标签名**。

---

## 一、为什么标签是地基

朋友圈是一个号面对所有人。不分人，会出三种事：

| 事故 | 例子 |
| --- | --- |
| **价格互相打架** | 卖几百元个人课的刷屏，被花几万元买企业服务的老板看到，他会觉得你不值这个价；社区公益价被企业客户看到，企业价就谈不下去 |
| **身份错位** | 政府、国企的对接人天天刷到你在卖课，觉得你太商业 |
| **渠道说不清** | 合作方带来的人，后来买了什么、该不该分钱、能不能单独推销，说不清，下次就没人愿意带人给你 |

所以标签只回答两个问题：**这条给谁看**；**这个人从哪来、买过什么、走到哪一步了**。答不了这两个问题的标签，不建。

## 二、一个必须知道的限制

微信朋友圈的「部分可见」和「不给谁看」选多个标签时取的是**并集**（只要属于其中一个标签就算），**选不出交集**（比如「既是老板、又问过价」的人）。

推出来的设计规则：

1. **身份只选一个**，而且每个身份标签本身就是发圈时要选的一群人
2. 需要交集的场景（比如只私聊问过价的老板）不靠朋友圈，靠**私聊**：按标签把人筛出来，逐个聊
3. 有少数人不管是什么身份都不该看到卖货内容，单独给他们一个「禁」标签

企业微信的客户标签可以按多个标签组合筛人，但朋友圈可见范围的逻辑类似。用户用企业微信时，照这套建，再按实际功能调整。

## 三、五个维度

前缀用一个字，加一个「·」，发圈选人时一眼能找到同一个维度的标签。

| 维度 | 单选 / 多选 | 回答什么 | 例子（按用户的业务改） |
| --- | --- | --- | --- |
| **身·** 身份 | **单选** | 他是谁、最可能买你什么 | 身·老板、身·政企、身·伙伴、身·同行、身·学员 |
| **源·** 来源 | 单选 | 谁带来的 | 源·某付费社群、源·公益活动、源·内容、源·转介绍 |
| **买·** 买过 | 多选 | 买过哪些产品 | 每个产品一个，比如 买·系统课、买·线下活动 |
| **阶·** 阶段 | 单选 | 走到哪一步 | 阶·新加 → 阶·活跃 → 阶·意向 → 阶·老客 |
| **禁·** 例外 | — | 谁不该看到卖货 | 禁·卖课（领导、长辈、很看重的大客户） |

### 身份怎么列

- 从**用户的产品线**倒推：每类身份对应一类他会买的东西，或一种要保护的关系（政企、伙伴、同行）
- 一个人对得上好几个身份时，**按顺序从上往下数，先对上哪个就选哪个**。顺序一般是：关系敏感的在前（政企、伙伴、同行），买得贵的其次（老板），数量多的个人在最后
- 数量最多的那一类（通常是学员）放最后，当作默认身份
- 「同行」和「想跟你学同一门手艺的人」要分开：前者不卖，后者是客户

### 几条规矩

- **标签用来筛人，备注用来认人**：行业、具体需求、报价、介绍人，都写备注。备注格式建议 `名字｜单位或身份｜一句话`
- **攒到 20 人以上再单独建标签**（建议起点），不到 20 人的先归到「其他」
- **拿不准的不打**，等他来互动了再补
- 「买过一次」看「买·」标签就知道，阶段里不另设「已付费」；「阶·老客」留给买过两次以上或给你转介绍过的人
- 渠道带来的人，没跟渠道方说好之前，**不单独向他推销**

## 四、每类内容给谁看（默认规则）

交稿时每条朋友圈都按这张表标出「所有人可见」「部分可见：……」或「不给谁看：……」。用户的 `标签体系.md` 里另有规则的，以用户的为准。

| 内容 | 默认可见范围 | 为什么 |
| --- | --- | --- |
| 生活、观点、思考 | 所有人 | 人设对谁都要立 |
| 低价个人产品的发售、价格、催单 | **不给谁看**：高客单身份（老板）、政企、同行、伙伴、禁 | 低价刷屏会拉低高客单客户对你的估价 |
| 高客单服务的案例、现场 | 所有人，**不写价格** | 案例对谁都是背书；价格只在私聊里说 |
| 学员喜报、作业成果 | 所有人；政企对接人比较敏感的话，不给政企看 | 证明「普通人也能做到」 |
| 讲自己吃饭本事的方法（怎么讲课、怎么获客） | 不给同行看 | 方法是给客户的，不是给同行抄的 |
| 只对某一类人的转化内容（比如宝妈专场） | **部分可见**：那一类身份 | 其他人看了是打扰 |
| 老客专属（早鸟、内部名额、复购优惠） | **部分可见**：阶·老客 + 相关的「买·」标签 | 让老客感到被区别对待 |
| 公益价、内部价、给某个单位的报价 | **不发朋友圈** | 一旦被别的客户看到，就再也收不回来 |

**同一个卖点，对不同身份换说法**：给老板讲「省了几个人的工资」，给个人讲「下班早一个小时」，给政企讲「干部职工的办公提质增效」。同一条内容要换说法时，拆成几条，分别设可见范围，不要写一条想讨好所有人的。

## 五、帮用户建一套（第一次用时）

### 先问清这四件事

| 要知道的 | 用来定什么 |
| --- | --- |
| 你卖哪些东西，大概什么价位 | 「买·」标签；哪些人不能看到低价 |
| 你的客户、合作方、需要保护的关系分哪几类 | 「身·」标签和顺序 |
| 你的好友主要从哪几个渠道来 | 「源·」标签 |
| 有几个号、各多少好友，主要用哪个 | 是否要加「号」维度；清理节奏 |

用户说不清的，从他的个人介绍、产品价目、上次发售方案里找，找到的拿去跟他确认，不替他定。

### 交付 `<moments>/标签体系.md`

1. 四条规则（单选身份、标签筛人备注认人、20 人再建、拿不准不打）
2. 标签清单：每个维度一张表；身份表要写顺序、是谁、能卖他什么
3. 每类内容给谁看：在第四节默认规则上按用户的产品改
4. 备注格式和两个例子
5. 老好友分批清理计划（见下）
6. 日常：新加好友当场打标签；每周复盘时升级阶段

标签总数控制在 **30 个以内**（建议起点），多了发圈选人时找不到。

### 老好友多（上千）时分批清理

| 批次 | 打谁 | 怎么打 |
| --- | --- | --- |
| 1 | 关系敏感、人数少的：政企、伙伴、同行、老板 | 凭印象搜名字，打身份，改备注 |
| 2 | 买过东西、参加过活动的 | **按群批量打**：一个课程群或活动群对应一个「买·」标签，再加上来源标签。在通讯录的标签里批量添加成员（微信版本支持的话可以直接从群聊里选人） |
| 3 | 第 2 批的人补身份 | 先全部打成默认身份，再把特殊的挑出来改掉 |
| 其余 | 不主动打 | 来互动了再补 |

先做第 1 批，做完就能安全地发卖货朋友圈了。

## 六、发售时怎么用标签

### 盘客户：A、B、C 对到标签上

| 分组 | 用标签怎么筛 | 怎么对待 |
| --- | --- | --- |
| A 高意向 | 阶·意向 + 阶·老客，以及买过相关前置产品的「买·」 | 发售前一天逐个私聊，邀请进预约名单 |
| B 有兴趣 | 阶·活跃 | 开售后私聊，带一个只属于他的细节 |
| C 观望 | 阶·新加，以及没打阶段标签的 | 只靠朋友圈，不主动私聊 |

再按身份过一遍：不是这次产品目标身份的人，A 类也不私聊；渠道带来、还没跟渠道方说好的人，先不私聊。

### 发售方案里要写清的

- 这次产品的**目标身份**和**要避开的身份**
- 每条朋友圈的**可见范围**（写进排期表的一列）
- 私聊名单：按上表从标签里筛，写清数量，不写名字

### 发售结束以后

1. 成交的人打上「买·<产品>」，阶段升一级（买过两次以上的升到阶·老客）
2. 问过价没买的升到阶·意向，留给下一期
3. 按「源·」统计这次每个渠道来了多少人、成交多少，写进复盘；合作方的部分按约定反馈给对方
4. 新冒出来的一类人超过 20 个，提醒用户考虑新建身份或来源标签，更新 `标签体系.md`

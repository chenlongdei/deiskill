# Claude Code 知识地图（道法术器用）

> 依据：笔记本「Claude Code 学习路线 2026-11-11」中的 29 个 YouTube 教程。其中 Anthropic 官方 5 个，中文 5 个；24 个首轮精选，5 个为补齐 CI、无头模式、SDK 缺口补搜。
> 原始问答：`01_知识地图/002—006`，按道、法、器、术、用各一问。
> 标「单一来源」的说法只有一个视频支持；标「资料外核对」的是我根据资料以外的知识补充或质疑的地方，使用前请自行验证。

## 先说结论

1. **它不是代码补全工具，而是能自己动手的 agent**：读写文件、跑命令、看报错、自己修。决定效果的主要不是模型本身，而是你给它搭的「鞍具」（harness）：记忆文件、权限、验证手段、钩子。
2. **三条贯穿全程的原理**：
   - 上下文是稀缺预算：约 5 万—10 万 token 以后质量明显下降。
   - 验证优先：没有可证伪的完成标准，它会「自信地宣布完成」。
   - 硬约束交给代码：安全底线用 Hooks 和权限规则实现，不靠提示词里的大写警告。
3. **2026 年的风向是「做减法」**：CLAUDE.md 越短越好，第三方 Skill 不要贪多，Plan Mode 和 think 关键词的地位下降，改用完成定义和 Effort 档位。2025 年及更早的教程有不少做法已经过时（见「过时做法」）。
4. **学习顺序**：先跑通「提需求 → 看它改 → 中断或回滚 → 清空」的最小闭环 → 再学记忆、权限、上下文和验证 → 再学工作流 → 再理解扩展体系背后的取舍 → 最后做自动化和实战。

## 道：理念与边界

| 原理 | 含义 | 出处 |
| --- | --- | --- |
| Agent harness | 模型像马，效果取决于鞍具：目录索引、分层规则、钩子、权限沙箱 | AI随风、Mark Kashef、官方团队 |
| 上下文是注意力预算 | 窗口标称很大，但约 5 万—10 万 token 后进入「变傻区」：偷懒、遗忘、跑题。常驻内容越少越好，其余按需加载 | JavaScript Mastery、The Coding Sloth、Simon Scrapes |
| 验证优先 | 模型会偏爱自己的产出；任务开始前就要定义能返回「失败」的验收标准：测试、类型检查、截图对比 | Simon Scrapes、Greg Baugues、官方团队 |
| 确定性优于祈求 | 提示词是概率性约束，安全底线要用 Hooks（退出码 2 阻断）和 deny 规则 | 官方 Hooks 视频、马克的技术工作坊 |
| 随模型升级做减法 | 新模型发布时，官方删掉了大量系统提示词；为旧模型打的补丁会变成负担 | AI LABS（Boris 访谈）、Simon Scrapes |
| 从盯操作到管目标 | 人从监督每一步，转为设边界、给背景、审结果；官方团队已大量在 Slack、Projects 里异步使用 | 官方团队圆桌（单一来源） |

**和其他工具的区别**：ChatGPT 只能对话，你要手动搬运上下文；Cursor 是以补全和行内 diff 为主的编辑器。Claude Code 是有系统权限的自主 agent，能跨文件干完整件事，还能脱离界面在 CI 里跑。注意：`/rewind` 只能撤销 Claude 自己写的文件，Bash 命令生成的东西撤不掉，要靠 Git 兜底。

**不该用的场景**：改一个错字这类琐碎修改（启动开销大于收益）；没有测试和验证手段的大规模重构；没有备份和沙箱的生产环境，尤其不要随便加 `--dangerously-skip-permissions`。

## 法：七套工作流

| 工作流 | 适合 | 核心步骤 | 出处 |
| --- | --- | --- | --- |
| Plan → Setup → Build | 从零起一个中大型项目 | 想清楚目标和里程碑，写轻量 spec → 七步准备（仓库、环境变量、精简 CLAUDE.md、自动更新的文档、插件和 MCP、命令和子代理、权限和 Hooks）→ 先交付 MVP 再迭代 | AI with Avthar |
| 完成定义驱动 | 日常任务（新风向） | 任务 + 边界 + 可机器验证的完成标准，事后看报告验收；不再强制先走 Plan Mode | Simon Scrapes（引 Boris，单一来源） |
| GitHub Issue 驱动 | 中大型应用的持续迭代 | 需求拆成 30—40 个原子 Issue → 命令拉取 Issue 做计划 → 写代码 + 测试 + 浏览器验证 → 提 PR → **新会话**独立审查 → 合并后 `/clear` | Greg Baugues |
| 波次并行 | 复杂全栈应用 | 脚手架 → 锁定设计规范 → spec 拆成多个波次 → `/goal` 循环 + 子代理并行 + Playwright 自测 → `/loop` 定时巡检 | Leon van Zyl |
| Worktree 并行 | 同时推进多个独立功能 | 每个分支一个目录、一个会话，分别测试后再合并 | The Coding Sloth、Avthar、Johnathan Mo |
| 上下文工程（PRP） | 需求复杂、要求高可靠 | examples + initial.md → generate-prp 生成蓝图 → execute-prp 分步实现，测试不过就自己修 | AI超元域（单一来源） |
| 六种动态工作流 | 治理偷懒、自评偏见、跑题 | 分类后执行、扇出再汇总、对抗验证、生成后过滤、淘汰赛、循环直到完成 | Mark Kashef |
| 无头 CI | 无人值守的审查和修复 | 安装 GitHub App → 在 Issue 或 PR 中 @claude → 自动写代码、提 PR、CI 失败后自己修 | 官方、The Gray Cat |

## 器：功能模块速查

| 模块 | 用途 | 关键点 | 限制与坑 |
| --- | --- | --- | --- |
| 三种形态 | 桌面端（零门槛，内置预览、点选页面元素）；CLI（管道、无头）；IDE 扩展（看 diff） | 新手和非程序员从桌面端开始 | 桌面端暂无 Linux 版 |
| 模式与权限 | 每步询问 / 自动接受编辑 / Plan（只读）；`Shift+Tab` 切换 | `settings.json` 的 allow、ask、deny，deny 优先；`deny: [".env*"]` 保护凭证 | `--dangerously-skip-permissions` 只在沙箱里用 |
| Auto mode | 减少「审批疲劳」 | 服务端先扫描提示注入；独立分类器只比对「用户意图」和「工具调用」 | 官方视频，单一来源 |
| CLAUDE.md | 每次会话自动加载的记忆 | 全局、项目、子目录、本地私有四层；`/init` 生成；当作索引用，控制在 200 行内；没有它时会读 `agents.md` | 用 `#` 就地追加规则：资料外核对，新版行为可能已变 |
| 斜杠命令 | 参数化的提示词模板 | `.claude/commands/*.md`，用 `$ARGUMENTS` 传参 | 只能人调用，模型不会自己触发 |
| Skills | 按需加载的操作规程 | 元数据 → 正文 → references 三层渐进加载；`disable-model-invocation` 禁止自动触发 | 运行时共享主会话的上下文 |
| Subagents | 隔离上下文的独立工作者 | `.claude/agents/`，可限定工具；探索过程留在子代理里，只回传结论 | 并行时用量成倍增长，要设数量上限 |
| Hooks | 确定性拦截 | 提交提示词、工具调用前、工具调用后、通知、结束五类事件；退出码 0 放行，2 阻断并把 stderr 反馈给模型 | 脚本出错会卡住整个会话 |
| MCP | 连接外部系统 | 数据库、浏览器（Puppeteer、Chrome DevTools）、GitHub、Notion、Context7 | 每个工具的描述都占启动上下文，不要贪多 |
| Plugins | 把 Skills、Hooks、Agents、MCP 打包分发 | `/plugins` | 装之前审查来源 |
| Checkpoints | 快照与回滚 | 双击 ESC 或 `/rewind`，可以只回滚对话、只回滚代码，或两者都回滚 | 撤不掉 Bash 生成的文件 |
| 上下文管理 | 控制 token 消耗 | `/context` 查看占比；`/compact` 可带保留指示；`/btw` 旁路提问，不写入历史 | 做完一个独立任务就 `/clear`，比 `/compact` 更好 |
| 无头模式与 Actions | 脚本和 CI | `claude -p`、`--allowed-tools`、`--output-format json`；`/install-github-app` | 按 API 计费 |
| Agent SDK | 用代码构建自己的 agent | Python / TypeScript | 资料里写的 `pip install agent-sdk` 与已知包名 `claude-agent-sdk` 不符：资料外核对，以官方文档为准 |
| Projects 与 Routines | 云端跨仓库的长期任务、定时巡检 | 每个子任务一个线程，自动提 PR、盯 CI | 用量消耗大，协调线程的 Effort 设低一些（官方，单一来源） |

## 过时做法 → 新做法

| 旧做法 | 新做法 | 可信度 |
| --- | --- | --- |
| 大任务一律先进 Plan Mode | 给出任务 + 边界 + 完成定义，让它直接做、自己验证 | **单一来源**（Simon Scrapes 转述 Boris）。Plan Mode 仍是官方功能；建议新手先用，熟练后再按任务取舍 |
| 在提示词里写 think hard、ultrathink | 调 Effort 档位，默认中档 | 多个来源一致 |
| CLAUDE.md 越详细越好 | 200 行以内，当作索引，其余按需加载 | 多个来源一致 |
| 只认 CLAUDE.md | 也支持 agents.md | JavaScript Mastery |
| 用大写警告约束危险操作 | Hooks + deny 规则 | 官方 |
| 一次装一大包第三方 Skill | 先裸跑，只针对反复出错的地方补几行（反向 Skill 制作法） | 多个来源一致 |
| 给子代理起「顶级架构师」这类头衔 | 让主模型自己派生，人只设数量上限 | Simon Scrapes |

## 术：20 个技巧（按学习顺序）

1. 截图直接粘贴（Mac 上也是 `Ctrl+V`）让它修 UI
2. 遇到不对立即按 ESC 中断；双击 ESC 或 `/rewind` 回滚
3. 一个任务做完就 `/clear`
4. 消息排队：它在干活时可以直接输入下一条
5. 长任务用 `Ctrl+B` 放到后台，用 `/tasks` 管理
6. 纠正它的错误后，把规则沉淀进 CLAUDE.md
7. CLAUDE.md 分层并渐进加载，正文只写路径指针
8. 用 `deny` 保护 `.env*`；只给它看 `.env.example`
9. 任务描述以完成定义收尾
10. 测试先行：先写会失败的测试，再写实现
11. 用浏览器 MCP 自己点击、截图验证
12. 先用 Opus 规划，再用 Sonnet 执行；琐碎活不用顶配
13. 用 `/context` 看占用，用 `/btw` 问边角问题
14. 大仓库维护一份 `codemap.md` 导航
15. 用 Hooks 做格式化和危险命令拦截
16. 反向 Skill：只把反复犯的错写成 Skill
17. 限制子代理数量，避免用量很快烧光
18. Worktree 隔离并行任务
19. 用语音输入大段背景（`/voice` 或外部语音工具）
20. 模型升级后清理过时规则（`/doctor` 相关命令：单一来源，资料外核对）

## 学习依赖

```text
L1 安装 → 模式切换 → ESC 中断 / 回滚            ← 安全底线
L2 CLAUDE.md（精简）+ settings.json 权限
L3 验证闭环：测试先行、浏览器截图
L4 上下文治理（/context、/clear）→ 按需写 Skill、接 MCP
L5 Subagents、Hooks、Worktree 并行
L6 Projects、Routines、GitHub Actions、SDK
```

关键依赖：没有验证手段（L3），就不要让它长时间自主循环（`/goal`）；单个 agent 用不顺时，不要上多个 agent（L5）。

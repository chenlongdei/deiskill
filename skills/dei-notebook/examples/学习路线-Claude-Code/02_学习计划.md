## 单元 1　上手：最小闭环

**观看顺序**
1. Teacher's Tech《Desktop App: Beginner's Guide》：免终端安装 → 三个标签页与绑定文件夹 → 做随机点名器 → 实时预览与点选元素修改
2. Tech With Tim《Full Tutorial for Beginners》：终端安装、登录 → 在 VS Code / Cursor 里启动 → 第一个井字棋
3. 马克的技术工作坊《从 0 到 1 全攻略》：`Shift+Tab` 切换模式 → `--dangerously-skip-permissions` 的风险 → 双击 ESC 回滚（只回滚代码、只回滚对话、两者都回滚）→ 截图粘贴

**注意**：Mac 上粘贴截图也要按 `Ctrl+V`；回滚撤不掉 Bash 命令生成的文件；auto mode 不等于没有防线。

**练习**
1. 新建空文件夹，让它做一个「带动效的抽奖转盘」单页，在浏览器里测试。
2. 把窗口缩到手机宽度，截图有问题的地方，`Ctrl+V` 贴进去让它修。
3. 故意提一个离谱的大重构需求，在它乱改时按 ESC，再双击 ESC 回滚到可用版本。

**验收**：能从零启动并登录；能说出当前处于哪种模式；完成一次「截图 → 修复」；失控时 2 秒内中断并回滚；做完一件事会 `/clear`。

**常见卡点**：Windows 下安装需要管理员身份运行 PowerShell；把要执行的命令直接贴进对话框（应该用 `!` 前缀或另开终端）；图省事一开始就跳过权限确认。

## 单元 2　核心操作

**观看顺序**
1. JavaScript Mastery《Full Course 2026》：上下文腐化原理 → CLAUDE.md 分层（全局、项目、`CLAUDE.local.md`）→ `/init` → `agents.md` 兼容 → `settings.json` 权限，现场演示 deny 拦截读取 `.env`
2. The Coding Sloth《1000+ Hours》：上下文衰减、`/context`、`/btw`、为什么 `/clear` 比 `/compact` 好
3. Simon Scrapes《Top 1%》：用 Effort 档位代替 think 关键词；完成定义三要素；清理过时规则

**注意**：CLAUDE.md 里引用其他文件用反引号写路径，**不要用 `@`**（`@` 会在启动时整份加载）；一个功能做完、提交 Git 后就 `/clear`。

**练习**
1. 建一个假的密码文件，用大白话让它设置「这个文件永远不准读」，再让它去读，确认被拦下。
2. `/init` 生成 CLAUDE.md，删到 40 行以内；把设计规范放进子文件，在 CLAUDE.md 里用路径指过去。
3. 让它先写会失败的测试，再写实现直到测试全部通过；再用带完成定义的指令让它自己循环修到底。

**验收**：CLAUDE.md 在 200 行以内且没有代码树；读取 `.env` 会被系统拦截；看得懂 `/context` 的占用分布；每个任务都用「任务 + 边界 + 可验证的完成标准」来描述。

**常见卡点**：CLAUDE.md 越写越长；相信它口头说的「已修复」；一个会话连做几件不相干的事。

## 单元 3　工作流

**观看顺序**
1. AI with Avthar《How I Start EVERY Project》前半部分：规划（两个核心问题、spec）+ 准备七步清单
2. JavaScript Mastery 中加数据库的章节：Plan Mode + `Ctrl+G` 编辑计划；**对照** Simon Scrapes 开头「Top 1% 不再盲目用 Plan Mode」
3. Greg Baugues《GitHub WORKFLOW for Complex Apps》：Plan → Create → Test → Deploy；在新会话里独立审查
4. AI随风《大型项目最佳实践》：codemap + 子目录 CLAUDE.md
5. Greg Baugues《47 PRO TIPS》中的 worktree 部分 + Mark Kashef《6 Dynamic Workflows》

**注意**：它会偏爱自己的产出，验收必须靠外部手段（测试、另开一个 agent 审查）；worktree 有运维成本（每个都要重新确认权限、配置环境），只适合相互独立的大功能。

**练习**
1. 写一个边界清楚、带完成定义的 GitHub Issue → 让它读取、实现、跑通测试 → 提 PR → `/clear`。
2. 在一个中型项目里建 `codemap.md` 和子目录规则，检查它是否按索引直达目标文件，而不是全库搜索。
3. 用 Subagents 扇出调查 → 再派一个只读的审查 agent 挑毛病，直到所有检查通过。

**验收**：开工前有 spec 或拆好的 Issue 清单；会话一直保持在健康水位；交付都有自动验证。

**常见卡点**：Issue 拆得太大；改一行 CSS 也开 Plan Mode；一个会话聊几十轮。

## 单元 4　扩展体系与原理取舍

**观看顺序**
1. Matt Kuda《Skills, MCP, Agents & Plugins》选型框架 → 马克的技术工作坊里 Skill 与 SubAgent 的上下文差异 → ByteByteAI《12 Features》
2. 官方《Hooks in Claude Code》全片
3. JavaScript Mastery 中上下文腐化的分析 + AI随风、官方团队圆桌里 harness 的演进
4. AI LABS《Setup Guide By The Creator》：删掉 80% 提示词、Safe mode
5. 官方《How auto mode works》全片

**选型速记**

| 需求 | 用 | 原因 |
| --- | --- | --- |
| 项目事实、硬性约定 | CLAUDE.md | 每次自动加载，所以要短 |
| 可复用的流程 | Skill | 按需加载，但和主会话共享上下文 |
| 要读大量文件的探查或审计 | Subagent | 独立上下文，只回传结论 |
| 必须 100% 执行的规则 | Hook | 确定性，不消耗 token |
| 连外部系统 | MCP | 标准协议；每个工具描述都占上下文 |
| 打包给别人用 | Plugin | 把以上几样一起分发 |

**练习**
1. 让它装两条自动规则：改文件前自动备份；拦住「删除整个文件夹」这类危险操作（说法见实操手册任务 8）。
2. 写一个只读的 `security-reviewer` 子代理扫全库，对比主会话的上下文占用。
3. 找出 CLAUDE.md 和 Skills 里 3 条「新模型自己就会」的规则，删掉，对比删前删后的效果。

**验收**：面对一个新需求，能 10 秒内说出该用哪种扩展；所有硬性规则都由 Hooks、权限或测试保障。

**常见卡点**：把读大量文件的重任务写成 Skill，结果撑爆主会话；装一堆第三方 Skill。

## 单元 5　自动化与实战

> 这一单元的问答没有依据资料，下面的命令请对照官方文档确认。

**观看顺序**
1. 官方《Building headless automation》：`claude -p`、`--allowed-tools`、`--output-format json`、session_id
2. The Gray Cat《GitHub Action: Automated PR Reviews》+ 官方无头自动化视频中 Issue 自动实现的演示
3. ExamPro《Claude Agent SDK Tutorial》：自定义工具、`stop_reason`（包名以官方为准：Python 是 `claude-agent-sdk`，资料外核对）
4. 官方《Getting started with Claude Code Projects》
5. Grace Leung《Build Your First AI Agent (No Coding)》

**注意**：无头模式和 Actions 按 API 计费，要设额度上限；Actions 里要配置好 `ANTHROPIC_API_KEY` 这个 Secret；脚本里不放行工具，进程会一直卡在等待确认。

**练习**
1. `cat meeting.txt | claude -p "提取行动项，输出 JSON 数组" --output-format json > tasks.json`
2. 给自己的仓库装 GitHub App，提一个故意留了 `console.log` 的 PR，看它自动审查。
3. （可选，偏开发）用 SDK 写一个带工具的小 agent。

**综合项目（为内容创作者设计）：每周内容排版自动化**

| 环节 | 做法 | 用到的单元 |
| --- | --- | --- |
| 准备 | 桌面端新建 `creator-os` 文件夹；品牌规范写进 `design.md`，CLAUDE.md 用路径指向它；`deny .env*` | 1、2 |
| Skill | `carousel-generator`：长文 → 5—7 张卡片文案（钩子标题、反直觉观点、论据、金句）→ 单文件 HTML 轮播 | 4 |
| 反馈记忆 | `content-memory.md`：每次审美修改都沉淀为规则 | 2 |
| MCP | Notion（读取待办素材）+ 浏览器（渲染、截图出图） | 4 |
| 自动化 | 每周定时任务：拉取「待处理」素材 → 排版 → 出图 → 回写 Notion，状态改为「待审核」 | 5 |

**验收**：一篇长文进去，自动出一组符合品牌风格的卡片，并回到你的看板里等你审核。

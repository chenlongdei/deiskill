# 学习路线：从一批教程学会一个软件或技能

用户已经把某个软件或技能的一批教程（多为 YouTube 视频）导入笔记本，要「从入门到精通」的学习计划和实操手册时读本文。提问的通用做法见 [asking.md](asking.md)。

## 核心原则

NotebookLM 的长处是答案有出处，短处是问什么答什么，容易停在表面。价值来自 Agent 自己做的四件事：

1. **设计问题**：按「道法术器用」分层提问，不问「XX 是什么」这类一句话就能答完的问题。
2. **查缺口**：找出「资料未涉及」的地方，以及不同视频说法矛盾、版本过时的地方。
3. **控数量**：**7 问封顶**，拿到整体深度内容就停，剩下的由 Agent 综合。
4. **做综合**：跨问题整合成计划和手册。出处写视频名或作者，不写 [n] 编号。Agent 自己补充的内容标「资料外补充」。

## 7 问封顶

整条学习路线最多问 7 个问题。每问开新对话，并自带完整背景（软件名、版本、读者是谁）。每个问题都要求「出处写视频名或作者，不要用编号」。

来源超过约 25 个时，要求「严格控制在 4000 字以内」，并收窄范围（如任务 8—10 个、案例 6 个）。NotebookLM 常常不遵守字数要求，真正起作用的是收窄范围。超限报错（`RPC response exceeded`）时，再缩小范围重问；重问计入 7 问。

| # | 问什么 | 用在 |
| --- | --- | --- |
| 1 | 资料盘点 + 缺口 | 判断要不要补搜 |
| 2 | 道 + 法：它是什么样的工具、适合谁、高手的工作流、各家分歧 | 知识地图 |
| 3 | 器 + 术：能做成哪些事、关键功能和限制、过时做法、高价值技巧 | 知识地图 |
| 4 | 用：真实案例（谁、拿它做了什么、怎么跟它说的、做出了什么）+ 学习先后 + 资料缺口 | 知识地图、手册案例 |
| 5 | 学习计划：单元 1—3 | 学习计划 |
| 6 | 学习计划：单元 4—5 + 综合项目 | 学习计划 |
| 7 | 实操手册：按任务组织（见 Step 4） | 实操手册 |

规则：

- **不写没有答案的问题清单**。凡是写进文件的问题，当场就问完；问不了的就不写。
- 补搜后不必重问第 1 问。
- 7 问之后，用户点名要某个单元或任务更深时才加问。先告诉用户要加几问（每次不超过 3 问），确认后再问。

## 道法术器用

贯穿全程的框架，既用来给单元分层，也用来设计提问角度。

| 层 | 回答什么 | 提问角度 |
| --- | --- | --- |
| 道 | 底层原理、设计理念：它为什么这样设计，解决什么根本问题 | 核心理念是什么？和同类工具的根本区别？什么情况下不该用它？ |
| 法 | 方法论与策略：什么场景用什么思路，工作流怎么搭 | 高手的完整工作流是什么？面对某类任务如何拆解？有哪些决策原则？ |
| 术 | 具体技巧和操作步骤 | 某件事怎么做？有哪些省时技巧、隐藏用法、常见坑？ |
| 器 | 功能、设置、模板、配套工具 | 有哪些关键功能？各自的边界和限制？可以配合哪些工具？ |
| 用 | 真实场景的应用和产出，以及如何衡量做得好不好 | 资料里有哪些完整案例？换到我的场景怎么用？怎样判断做得好？ |

## 文件位置

全部放在笔记本存档文件夹下的 `学习路线/`，提问时用 `--dir` 指定子目录。每份问答只有问题和回答。

```text
<笔记本>/学习路线/
├── 问答/               7 问的原始问答（001—007）
├── 01_知识地图.md      Step 2 综合
├── 02_学习计划.md      Step 3 综合
└── 实操手册.md         Step 4
```

## Step 1 资料盘点（第 1 问）

```text
请逐一列出本笔记本里的每个来源：标题、作者，适合入门/进阶/高级哪个水平，
讲的是哪个版本或哪个时间段的产品，主要覆盖哪些功能或主题，有没有实操演示。
最后指出：哪些主题被多个来源重复讲到，哪些重要主题只有一个来源，各来源之间有哪些说法不一致。
```

Agent 检查：水平分布是否失衡（例如全是入门）、版本是否过旧、明显缺了哪块。缺口大时，告诉用户需要补哪类视频，并给出建议的搜索关键词，而不是硬做计划。

## Step 2 知识地图（第 2—4 问）

第 2、3 问各问两层，第 4 问专问案例：

```text
（第 4 问示例）请整理资料里所有完整的应用案例，按场景分类。每个案例写清：
谁（视频作者），拿它做了什么，原话大概是怎么跟它说的，过程中改了几次、怎么改的，最后做出了什么。
优先非程序员也能照着做的案例。再说明学会它的先后顺序（学 B 之前必须先会 A），以及这批资料的主要缺口。
出处写视频名或作者，不要用编号。
```

Agent 综合成 `01_知识地图.md`，包括：五层要点、学习先后、各来源的分歧和 Agent 的判断、资料缺口。

## Step 3 学习计划（第 5—6 问）

把知识地图的要点和学习先后写进问题，请 NotebookLM 给出每个单元该看的视频和片段。

```text
我想从零学到精通。请按以下单元，为每个单元给出：
学习目标；按顺序该看哪些视频的哪些片段（有时间点就写）；看完要做的练习；怎样算学会；常见卡点。
单元：1 上手（器+术的最小闭环）2 核心操作（术）3 工作流（法）4 原理与取舍（道）5 实战项目（用）
```

单元划分是通用模板：Agent 按知识地图调整单元名称和数量（4—6 个都可以），保持「先能用，再会用，再懂为什么，最后做出东西」的顺序。练习一律写成「做成一件事」，例如「做一个抽奖转盘网页」，而不是「配置某某参数」。

`02_学习计划.md` 的结构：

```markdown
# <软件> 学习计划
## 总览：单元一张表（主题｜学完能做到什么｜核心视频｜建议用时）
## 单元 N：<名>
- 观看顺序：视频 + 片段 + 看的时候注意什么
- 练习：由易到难 2—3 件事
- 验收：能独立做成 X
- 常见卡点
## 资料缺口
```

## Step 4 实操手册（第 7 问）

**手册是教人用的，不是给程序员看的配置文档。** 读者默认是没有技术背景的人，标准是初中文化能看懂、复制就能用。

写作规矩：

1. **按「我要做成某件事」组织**，不按功能菜单组织。每个任务开头写「做完你会得到……」。
2. **教人怎么跟 AI 说，不教手写配置**。凡是 AI 自己能生成的东西（配置文件、规则文件、技能、自动化、权限设置），手册只给一段可复制的大白话指令，让 AI 去做；不贴 JSON、YAML、代码。确实要让读者知道的概念，用一句人话加一个生活比喻讲清楚。
3. **指令写成三段**：给什么材料 → 做什么、输出成什么样 → 不能破的规矩。规矩那一段防止 AI 乱编、乱改。
4. **每个任务都要有「怎么算成功」**：看到什么画面、拿到什么文件。
5. **放真实案例**：单独一节「看看别人怎么玩」，6—8 个案例，写清谁、做了什么、怎么跟 AI 说的、做出了什么、你可以怎么照搬。案例来自第 4 问。
6. 一句一意，动词开头（打开、复制、粘贴、拖进）。不编数字：耗时、效果没有出处就不写。
7. 不写「资料缺口」「单一来源」这类研究笔记；它们放在知识地图里。只在会让读者踩坑的地方，提醒一句「这一步以官方说明为准」。

第 7 问示例（软件名、读者按实际替换）：

```text
请为完全不懂技术的新手，整理用 <软件> 做成 8—10 件常见事情的方法。每件事写：
做完能得到什么；用大白话怎么跟它说（给一段可以直接复制的示例原话）；怎么判断做成了；最常见的 2 个翻车和怎么救。
凡是能让它自己生成的设置和文件，都写成「怎么跟它说」，不要给配置代码。
最后列出新手最常遇到的 6 个问题和解决办法。严格控制在 4000 字以内，出处写视频名或作者，不要用编号。
```

`实操手册.md` 的结构：

```markdown
# <软件> 实操手册｜<一句结果句>
> 一句话说清：谁看完能做成什么
## 先看结果：用它能做成什么（3—5 个成品，一句话一个）
## 准备：10 分钟装好并做出第一个小东西
## 任务（每个任务一节）
### 任务 N：<动词 + 结果>
做完你会得到……
👆 复制这段话发给它：
（三段式大白话指令）
怎么算成功 / 常见翻车 → 怎么救
## 看看别人怎么玩（案例）
## 常见问题
## 附录：全部指令速查
```

告诉用户各文件的路径，并用几句话说明：计划的主线、最值得先看的 3 个视频、资料里最大的缺口。

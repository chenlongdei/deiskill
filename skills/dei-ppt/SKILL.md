# dei-ppt 演示 PPT

## 使命

做一套讲者站上台就能用的 PPT。要求：

- 每页只有一个重点，听众的注意力留在讲者身上。
- 页面顺序就是讲者自己说话的顺序。
- 图和截图都是真的。
- 讲稿已经写进演讲者备注。
- 卡片和它上面的字打成组，入场动画写好；讲者在 Keynote 里还能接着加。

## 铁律

1. **先读偏好**：动笔前读 `references/preferences.md`。这是讲者亲手改稿留下的规则，优先级高于本文件其余部分。
2. **一页只放一个重点**：标题，加一个主体（指令框、一组卡片、截图三选一），再加一行补充，最多这三层。手册章节和限时放到右下角写成一行小字；讲者口头会讲、人人都会做的步骤，不上屏。细则见 `references/theme-mode.md` §3。
3. **一份内容文件出全部东西**：PPTX、预览图、逐页讲稿、签到轮播都从同一份内容文件生成。改东西只改内容文件，不手改 PPTX。
4. **讲者改过的版本就是正本**：讲者在 Keynote 或 PowerPoint 里改过之后，不再用生成版覆盖它。先跑 `keynote_diff.py` 找出改了什么，把改动同步回内容文件，再重新生成那些没被改过的产物（例如签到轮播）。备用 PDF 从正本导出。
5. **证据优先**：
   - 能放真截图、真指令、真文字，就不放金句页和占位框。截图还没有、但手里有真实文字的（比如提示词原文），直接把文字放进框里。
   - 案例数字用「能直接用、当场能核实」的口径，宁可保守。
6. **事实可查**：案例、数据、引文都要有出处。引文版本不确定的，在清单里标「待核」。工具的「要注意」按通用情况写，在清单里提醒讲者按自己的使用感受改。
7. **图里不放字**：标题和要点一律用可编辑的文本框。
8. **内容从手册来，不瞎编**：
   - 手册（或讲者确认过的方案、逐字稿）是唯一的内容来源；主题图只决定配色、背景和 logo，不提供任何内容。
   - 没有手册或方案，就先停下来要，不凭一张海报和一个题目编一套 PPT。
   - 动手页上学员要发的指令，从手册原文逐字复制，不改写；右下角标出对应的手册章节（`foot(s, "4.1")`），讲者和学员能对上号。
   - 步骤、工具、案例、数字、引文，在手册里找不到就不写；觉得缺了，在清单里列出来问讲者，或者建议讲者先补进手册。
   - 手册和 PPT 冲突时（例如讲者现场改了做法），先改手册或问讲者，再改 PPT，两边保持一致。

## 两种出法（Step 0 定下来）

| | 白底版 | 主题版 |
| --- | --- | --- |
| 什么时候用 | 政企、培训，讲者没给主题图 | 讲者给了海报、主视觉或品牌色（沙龙、活动） |
| 风格 | 白底黑字，唯一强调色是红 E60012 | 从主题图取色，配渐变背景；logo 照搬原样 |
| 引擎 | `scripts/deck_engine.py`（Python） | `scripts/deck_engine.js`（Node + pptxgenjs） |
| 一条命令 | `python3 <内容文件>.py <PPT 目录>` | `python3 scripts/build.py <内容文件>.js <PPT 目录> --name <文件名> [--checkin 签到轮播] [--pdf]` |
| 规范 | `references/style.md` | `references/theme-mode.md` |
| 模板 | `examples/` 里的内容文件 | `templates/theme_deck_template.js` |

讲者给了主题图，就一律用主题版，并且讲者原来的「白底」偏好在这里让位于主题图。其他规则（一页一个重点、讲稿口吻、证据优先）两种出法通用。

Windows 上把命令里的 `python3` 换成 `python`。命令都相对本 Skill 的目录写。

## 流程

### Step 0 弄清楚四件事（缺哪项问哪项，一次问清）

- **手册在哪（必需）**：学员手册、方案或逐字稿，这是 PPT 的内容来源。先通读手册，列出「章节 → 页面」对照表（哪一节出哪几页、哪些指令要上屏），后面逐页写的时候照着这张表。没有手册就停下来要。
- **讲给谁**：单位、听众构成、时长。这决定案例往哪个行业靠、出多少页（90 分钟大约 60 页；一个小时的实操大约 40 页正片，另加隐藏备用页）。
- **讲者是谁**：人物页的背书、本地案例、结果数字。讲者有个人案例库就从里面取，没有就问。另外问清他平时用哪些工具：方法页写讲者自己的工具链，不写通用做法。
- **讲者怎么说话**：要逐字稿或过往课程录音的文字稿，按 `references/narrative.md` 提取表达顺序和口头禅。
- **有没有主题图**：有，就走主题版。主题图只管样子；顺手问一句有没有 logo 原图（透明底的 PNG 最好）和讲者照片。

### Step 1 环境自检（第一次在这台电脑上用时）

```bash
python3 scripts/build.py --doctor
```

缺什么，它会按系统给出一条安装命令，讲者同意后再装：Node.js、在 `scripts/` 下 `npm install`、`pip install python-pptx pillow pymupdf numpy`、Keynote 或 LibreOffice 二选一、思源黑体。

### Step 2 定结构

按 `references/narrative.md` 的骨架排。沙龙、实操课的结构见 `theme-mode.md` §6：签到轮播 → 开场 → 每一轮「指令 → 打分 → 揭示」→ 收尾 → 服务 → 封底，另加隐藏备用页。

**确认点**：先给讲者看每段的页数和每段的一句话价值，确认后再逐页写。讲者已经确认过方案的，可以跳过这一步。

### Step 3 主题版：适配主题图

```bash
python3 scripts/poster_theme.py palette <海报>                       # 12 个主题色，贴进 createDeck({theme:{colors}})
python3 scripts/poster_theme.py backgrounds <海报> <PPT>/assets      # 三张背景图
python3 scripts/poster_theme.py logo <图> <x0,y0,x1,y1> <输出.png>   # 从海报上抠 logo；深色底白字的加 --invert
```

生成的背景要和海报放在一起比一比：颜色太灰、层次不够的话，就调 `backgrounds()` 里的亮度和饱和度，或者按海报手工改。封面按 `theme-mode.md` §1.5 排；讲者说「封面很好」以后，就不再改。

白底版用 `gen_images.py` 生成主视觉和插图，风格串见 `references/style.md`。

### Step 4 逐页写内容文件

- **主题版**：把 `templates/theme_deck_template.js` 复制到 `<课程文件夹>/_scripts/<项目>_deck.js`。优先用页面模板 `D.P.*`；自定义页用小部件拼，卡片用 `grp()` 打组，用 `anim()` 加动画（节奏见 `theme-mode.md` §5）。
- **白底版**：复制 `examples/` 里的 `deck_content.py`，开头写 `from deck_engine import *`。

每一页都按 Step 0 的「章节 → 页面」对照表来写：

- 指令照手册原文逐字复制。
- 动手页右下角标出手册章节。
- 讲稿的内容也从手册对应章节来，用讲者的口吻，写成能直接念出来的句子，（括号）里放动作提示。
- 手册里没有的东西，不往 PPT 里加。

还没截到的图，用 `ph()` / `PH()` 占位。

### Step 5 生成与自查

```bash
python3 scripts/build.py <内容文件>.js <课程文件夹>/PPT --name "<文件名>" --checkin 签到轮播 --pdf
```

脚本会自查三件事：每页有讲稿、文字没有溢出风险、动画目标都找得到。然后用 Keynote（没有就用 LibreOffice）渲染出 `preview/`，隐藏页也出图，文件名带「_隐藏」；再拼出 `contact_*.png`，最后写 `逐页讲稿.md`。

**逐张看 contact 拼图**，按 `theme-mode.md` §7 验收：

- 没有一页超过三层。
- 辅助信息都在角落。
- 每页内容都能在手册里找到出处，指令和手册原文一字不差。
- 卡片不空、不偏。
- 中文显示正常。

看出问题就改内容文件，重新生成，直到全部通过。

### Step 6 交付

交给讲者这些：

- PPTX（以及签到轮播、备用 PDF）
- 逐页讲稿.md
- preview/
- 课前准备清单.md，写清：
  - 要实测的功能，以及跑不通时的备用讲法
  - 要补的截图
  - 要核对的引文和数字
  - 要讲者按自己感受改的地方（比如工具的「要注意」）
  - 现场提醒（字体、logo、超时砍哪几页、隐藏页怎么用）

另外提醒讲者两件事：

- 会场电脑要装思源黑体，或者直接放备用 PDF。
- 引擎已经写好默认动画，在 Keynote 里还能继续加。

### Step 7 学讲者的改稿（讲者交回改版时）

```bash
python3 scripts/keynote_diff.py <生成版.pptx> <改版.key或.pptx> <输出目录>
```

`.key` 会先复制一份再用 Keynote 导出，不碰原文件。看 `diff.md` 和 `changed_*.png`，写 `改稿分析.md`：改了什么（事实），为什么改（推断，请讲者确认）。确认后：

1. 把可复用的规律追加进 `references/preferences.md`，注明日期和来源项目。版式、写法层面的规律，同时写进 `theme-mode.md` 或 `style.md`。
2. 把讲者改的字、数字、照片同步回内容文件，重新生成讲者没有改过的产物，比如签到轮播。

## 缺少信息时

- 没有讲者照片：放竖版占位框，列进清单。
- 没有 logo 原图：从海报上抠，在清单里提醒讲者换原图。
- 数字说不清口径：用保守的那个，在清单里标「待核」。
- 讲者没时间确认结构、又急着要：先按方案出一版，在交付消息里写清哪些地方是我替他定的。

## 边界与停止条件

- 渲染器、字体缺失：预览会失真（中文变成空白或衬线字体）。先跑 `--doctor`；装不上就跳过预览，交付时说明这一版没看过预览。
- 讲者改过的正本不覆盖。生成版和正本冲突时，停下来问讲者。

## 输出

```text
<课程文件夹>/
├── _scripts/<项目>_deck.js|py   内容文件（唯一源）
└── PPT/
    ├── <名称>.pptx               可编辑，带讲稿、分组和动画
    ├── 签到轮播.pptx             主题版：每页 15 秒自动翻，循环播放
    ├── <名称>（备用PDF）.pdf
    ├── 逐页讲稿.md
    ├── 课前准备清单.md
    ├── 改稿分析.md               有改版时才有
    ├── assets/                   背景、logo、照片、二维码
    └── preview/                  逐页图 + contact 拼图
```

## 禁止事项

- 不编造案例、数字、引文；不写对方单位没有公开的内部信息。
- 不画真实人物的肖像。讲者照片只用讲者本人提供的。
- 不覆盖讲者改过的 .key / .pptx。
- 讲师照片、背书和学员案例，都要讲者确认后才上屏；学员案例还要先问过学员本人。

完成当前任务后直接结束。用户的请求超出本 Skill 范围，或询问下一步时，用一句话说明还需要哪种能力，不点名其他 Skill；当前环境已经安装 `dei` 时，补一句「可以用 `$dei` 继续」。

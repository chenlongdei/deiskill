# 新案例入库

## 0. 用户给什么

越原始越好：录音转写、截图、聊天记录、任何数字（原来多少时间、多少人、多少钱，现在呢）、能不能点名。不够时一次问清缺的那几项。

## 1. 归类

| 问题 | 选项 |
| --- | --- |
| 谁做的？ | 亲手交付 / 学员 / 授课 / 个人成绩 |
| 讲给谁最有用？ | 老板 / 个人 / 政企 / 社区 / 学员（可多选） |
| 解决哪类问题？ | 用 `library.md` 里的常用词 |
| 能不能点名？ | 可点名 / 匿名 / 不对外 |

一个项目里有的部分是亲手做的、有的是学员做的，拆开写，各自标清楚。

## 2. 去伪存真

- 事实数字直接用；推算的写依据。
- 去掉对方追问时答不上来的说法。
- 不拉踩，客观描述。

## 3. 算账

| | 原来 | 现在 | 换算成一年 |
| --- | --- | --- | --- |
| 时间 | | | |
| 人力 | | | |
| 金钱 | | | |
| 产量 | | | |

没有金额时，用工序对比讲（「一天 1 条 → 一天 9 条」），不硬造金额。

## 4. 提炼

- **一句话结果标题**：写结果，不写过程。
- **谁会代入**：哪类读者看到会想「我也有这个问题」？
- **能撑哪条观点**：证明哪条非共识？
- **反常识细节**：例如「主理人原来抵触 AI」。这种细节最容易被记住。

## 5. 产出

1. 案例卡片写进 `05_案例库/<年份>_<短名>.md`（格式见 `library.md`），跑 `profile_lib.py index`。
2. 判断要不要进主介绍：比现有同类案例更硬（数字更大、读者更广、可点名）就替换或新增；否则只留在案例库，定制时再调用。
3. 改到的介绍文档：正文、首屏数字、估算口径附录、PPT 素材清单，前后对得上。
4. 原始材料放进 `03_参考资料/`，按编号命名。
5. 按 `publish.md` 重新生成 PDF。

最后用一段话告诉用户：这个案例归在哪、标题是什么、改了哪些文件、哪些数字是推算的。

# 介绍库的结构与建库流程

## 一、目录

```text
<介绍库>/
├── CLAUDE.md                 可选：这个人的偏好、价格、写错过的事实、「用户说什么就做什么」的约定
├── profile.json              品牌名、英文副标、城市，PDF 封面和页眉用
├── 01_个人介绍/              唯一需要编辑的源文件
│   ├── 个人介绍_<读者>版.md   按读者分版本，例如「企业与个人版」「政企与社区版」
│   ├── 人物档案.md            经历时间线、做事原则和背后的故事、招牌观点、可讲的故事清单（背景资料，不出 PDF）
│   ├── 自我介绍话术.md        四类对象 × 1 / 3 / 10 分钟
│   ├── PPT_个人介绍页.md      一页人物介绍 + 案例页模板
│   ├── 定制/                 按主题、场合定制的一次性版本
│   └── 历史版本/
├── 02_PDF/                   由脚本生成，不手改
├── 03_参考资料/              只读：原始文件、录音转写、梳理对话
│   └── 00_原始文件/
├── 04_工作流程/              可选：这个人自己的补充流程
└── 05_案例库/                一案一卡
    ├── 案例索引.md            由脚本生成
    └── <年份>_<短名>.md
```

`profile_lib.py init <路径>` 会补齐缺的目录和 `profile.json`，不覆盖已有文件。

`profile.json`：

```json
{
  "name": "显示名",
  "brand_en": "英文副标，可留空",
  "city": "城市",
  "contact": ""
}
```

## 二、案例卡片

一个案例一个文件，文件名 `<年份>_<短名>.md`。frontmatter 是筛选依据，必须填：

```markdown
---
title: 老板每天少算 2 小时账，200 多个号一套系统管起来
who: 亲手交付            # 亲手交付 / 学员 / 授课 / 个人成绩
audience: [老板, 个人]    # 这个案例讲给谁最有用：老板 / 个人 / 政企 / 社区 / 学员
industry: 连锁门店 摄影
problems: [获客, 算账, 内容矩阵]
numbers: [每天 2 小时, 200~300 个号, 2 万条]
public: 可点名            # 可点名 / 匿名 / 不对外
year: 2026
---

## 一句话
（30 字以内，口头能直接说的版本）

## 原来
## 做了什么
## 结果（事实）
## 算一笔账（估算，写依据）
## 讲给谁、怎么讲
（对老板强调什么，对个人强调什么；能支撑哪条观点）
## 素材
（截图、照片、原话在哪里；没有就写「待补」）
```

- `problems` 用短词，同一个意思用同一个词（「获客」不要一会儿写「引流」一会儿写「拉新」），筛选才准。常用词：获客、内容、算账、算薪、录入、防漏洞、政策、汇报材料、知识库、学习、副业、晋升、教学、家庭教育。
- `public: 不对外` 的卡片只在内部参考，不进任何对外成品。

## 三、建库流程（用户第一次来，手上是一堆素材）

1. **通读素材**：录音、旧介绍、和别的 AI 的梳理对话都读完，再开口。
2. **去伪**：先挑出问题，再动笔。常见的是这几类：
   - 别人做的写成了自己做的；
   - 数字没有来源，或被放大（「回报率 30 倍」「效率提升 80%+」）；
   - 一个案例被并进另一个案例；
   - 词太冲、太玄，或在拉踩同行。
   逐条列给用户确认，用户纠正的以用户为准。
3. **取精**：列出站得住的硬货，分三层证据：
   - **做出来的**（亲手交付）：证明能交付；
   - **教出来的**（学员）：证明方法能复制；
   - **被认可的**（课程、内训、社群、媒体）：证明有人背书。
4. **由表及里**：去掉行业标签，找出所有案例背后的同一件事，写成一句话定位。例：「把说不清、天天重复的活理成流程，用 AI 固定下来，再把人教会。」
5. **定版本**：问清楚主要读者，分版本写（见 `writing-rules.md`）。
6. **拆卡片**：每个案例拆成一张卡片，跑 `profile_lib.py index`。
7. **存原件**：用户给的原始文件放进 `03_参考资料/00_原始文件/`，合并同类的转写稿，重新编号命名。

## 四、背景资料入库（用户发来讲自己经历的录音、分享稿、访谈）

这类材料讲的是「这个人是怎么走到今天的」，不一定是案例，但讲长版自我介绍、开场、讲师介绍时最需要。

1. 原件放进 `03_参考资料/00_原始文件/`，转写稿放进 `03_参考资料/`，文首写清场合、日期和转写错字对照（品牌名、工具名常被听错）。
2. 提炼进 `01_个人介绍/人物档案.md`：
   - **经历时间线**：时间 / 发生了什么 / 能说明什么；
   - **做事原则**：每条原则配一个真实故事，没有故事撑着的原则不写；
   - **招牌观点**：本人原话里站得住的判断，改成大白话；
   - **可讲的故事**：一句话版本 + 适合讲给谁；
   - **对外不讲的**：对同行、其他社群和个人的评价，前雇主的名字等；
   - **和已有材料对不上的地方**：逐条列出，等用户确认，不擅自改已有介绍和卡片。
3. 材料里出现新的案例或背书，按 `case-intake.md` 另建卡片，跑 `profile_lib.py index`。

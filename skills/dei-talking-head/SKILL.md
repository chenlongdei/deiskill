# dei-talking-head 真人口播剪辑

## 使命

把一条随手录的真人口播，剪成刷到就想看完的竖屏成片：废话和口误删干净但意思一点不变，节奏紧、字幕大，讲到结构就画给观众看，每一刀都经得起听。工程用 `plan.json`（剪什么）和 `scenes.py`（画面）描述，改一处只动一处。

## 铁律

哪些写死、哪些不写死：**不能出错的写死**——删改要用户确认、刀口落在静音里、字幕区和平台安全区不放东西、素材能商用、不碰原片和旧版；**画面怎么排给默认值、留自由度**——位置、样式、版式顺序、动画方式，Agent 按内容判断，打破默认时在 `画面方案.md` 写一句为什么。


1. **删改清单先给用户确认再剪。** AI 找、用户拍板。结论、数字、否定词（不 / 不是 / 没有）、有实际作用的「然后 / 其实」不删；演示、等待、卖关子的停顿是内容，不删。
2. **每一刀都要经得起听。** 静音门限按这条录音的底噪和说话声自动定（不写死 -35 dB，录得小声的原片会把句尾轻声当静音，「话没讲完就切了」），句尾多留 0.15 秒；刀口落在静音里；被删的词不能留尾音（「当它是」删了，「是」的半个音不能接在下一句前面）；留下的词不能被削掉尾巴；**句子中间短于 0.45 秒的停顿不切**，只在句与句之间收气口。切碎了用户会听出「卡了两三下」。
3. **每次剪完都跑刀口核对**（`刀口核对.md`），读一遍；不对就用 `probe.py` 找静音、改 `plan.json` 重剪。
4. **图解画结构，不复述口播。** 观众已经听过、看过字幕，再把原句打一遍没有增量。用图标、箭头、对比、计数、流程。
5. **每条视频按这条内容设计画面，不照模子刻。** 先写 `画面方案.md`（每段在讲什么 → 选哪种版式 → 为什么），版式至少 3 种（整屏图解 / 人像 + 横条 / 侧边贴纸 / 大字砸屏 / 空镜 / 纯人像留白），开头钩子、第一个图解、出场顺序不跟上一条一样；写完跑 `variety.py`。用户原话：「重复有价值，但位置、呈现顺序、模块几乎一样，就太单调了」。
6. **位置、样式按内容定，有默认值，不是规定。** 用户原话：「不要写死，有的东西可以写死，但有的你要给他一些自由度」。贴纸放哪、用什么外观、两个元素要不要放在相邻或同一处做接力过渡，按这一段在讲什么决定（`slot="同上"` 就是给接力用的）；没有特别想法时才交给默认的随机位置，避免全挤在左上角（WorkBuddy 版的问题）。常驻标题和图解标题的样式同理：默认每条自动换，内容需要时在 plan.json 指定。近景脸大的原片在 plan.json 写 `face_box`。
7. **字幕区不放东西。** 字幕从 y≈1130 开始，图解内容放在 560–1060；`build.py` 发现有元素压进字幕区会报 ⚠，必须改掉再渲染（WorkBuddy 版出现过字幕压住图解标签）。
8. **要有呼吸感。** 整屏图解时常驻标题让位，顶部只留一层；一屏最多 3 组元素；观点段可以只有人像和字幕。
9. **对比要具体、要停得住、要接力。** 比两样东西时：两边同屏、同一个输入、各自的结果（一段文字 vs 一个文件），停留到口播讲完；后面的结论（「聊天机器人」「AI Agent」）挂到同一组卡片上变过去，不换新页面。图标一闪而过等于没对比。
10. **跳切换景别，两次至少隔 2 秒。** 用 1.0 / 1.12 交替推近遮跳切；不用交叉溶解（两张脸重影）。
11. **音效宁轻勿冲。** 每个画面动作配一个；打字动画用一段轻的键盘声，不用一下一下重击；砸字音少用。
12. **配乐明亮、大调、听得见。** 按真实响度（LUFS）校准：口播段配乐比人声低 14 LU（`bgm_lu`）；说话和停顿之间只差约 2 dB（停顿时音乐不「涌」上来）。旧版按 RMS 压 25 dB，实测低了 23.7 LU，用户说「有，但又像没有」。小调、神秘感的曲子不用；手机外放听不到低频，选钢琴、拨弦、吉他这类中高频有存在感的。
13. **素材都要能商用，且不强制付费账号**：图标 IconPark（随 Skill 附带）、空镜和音乐 Mixkit、音效默认 Mixkit 免费音效（配了 ElevenLabs key 才用它生成）或用户自己的可商用库。「仅供学习交流」的素材不进成品。
14. **剪完要听审。** 我只能抽帧看画面、转写听文字，听不到真实的声音。成片交给能听音频的模型（默认 Gemini，经 `agy`）按 30 秒一段审；**第一次上传前先问用户**；它的每一条都回原片核实再改。
15. **不碰原片，不覆盖旧版。** 每次出片换新文件名（v1、v2…）。

## 流程

命令都相对本 Skill 目录；Windows 上 `python3` 换成 `python`。需要 jieba / numpy / soundfile 的脚本用装了它们的 Python（`doctor.py` 会告诉你缺什么）。

### Step 0 准备

- `python3 scripts/doctor.py`，缺什么按 `references/setup.md` 给安装命令，**用户同意后再装**。
- 用户还没录的，先讲录的规矩（method.md 第 0 节：说错停 2 秒、从句首重说；演示时嘴上说一句「看这里」）。
- 一次问清：原片在哪；工程放哪（这件事已有项目文件夹就放它下面；没有就 `python3 scripts/dei_workspace.py where` 的 `output` 下 `口播剪辑/YYYY-MM-DD_HHMM_主题/`）；口播里有哪些专有名词（产品名、英文词）。
- 读 `references/method.md`。用户给了对标视频的，先看它的节奏、字幕和图解。

### Step 1 建工程、转写

`python3 scripts/new.py <工程> --source <原片> --title "常驻标题" --names "Codex,Obsidian,DeepSeek"`

产出 `逐字稿.md`（原片时间码、长停顿）、`plan.json` 草稿、HyperFrames 骨架。原片超过 1 GB 加 `--link`。

### Step 2 删改清单（用户确认）

读完整逐字稿，按 method.md 第 2 节改 `plan.json`：`keep`（保留段 + 内容）、`cut`（删掉的段 + 理由）、`caption_fixes`（转写错字）、`keywords`（字幕高亮词）。下刀前对拿不准的接缝跑 `probe.py`。把删改清单讲给用户听，**确认后再剪**。

### Step 3 剪

`python3 scripts/cut.py <工程>` → 剪、提速、人声处理、重新转写、字幕分组，写 `删改清单.md` 和 `刀口核对.md`。读刀口核对，有吞字或残音就改 `plan.json` 再跑。

### Step 4 画面

1. **先写 `画面方案.md`**（按 `references/scenes.md`「先定画面方案」）：逐段写口播在讲什么类型（框架 / 清单 / 对比 / 因果 / 反例 / 数字 / 故事 / 观点 / 金句）、选哪种版式和图解写法、为什么。从内容里找这条独有的画面（讲「窄人群」就画一个圈越缩越小，不套通用的左右对比卡）。给用户看一眼再写代码。
2. 照方案写 `scenes.py`。`scenes_example.py` 只当函数用法的参考，**不复制它的结构、位置和顺序**。时间优先用 `W("口播里的字")`。
3. `python3 scripts/variety.py <工程> [--with <上一条工程>]`：和最近几条、和示例比版式序列、开头钩子和写法，报 ⚠ 就回方案里换。用户点名风格（如「参考苹果」）时，用 `colors`、`caption_style`、`EXTRA_CSS` 换整套气质（scenes.md「换风格」）。
4. 用到的品牌 logo 放 `hf/assets/logos/`（官方素材或 theSVG）；升华的句子要垫空镜的，从 Mixkit 下可商用的竖版素材放 `hf/assets/broll/`，在 scenes.py 里用 `broll()`。
5. `python3 scripts/build.py <工程> --snap auto` 出关键帧（首帧 + 每段画面各一张；也可以写秒数 `--snap 3,36,82`），逐张看：字有没有挡脸、出画、挤在一起（有没有呼吸感），对比看不看得懂。改到满意。

### Step 5 声音、出片

1. 配乐：按这条的调性（讲解 / 故事 / 教程 / 观点 / 号召）从用户的配乐库或 Mixkit 挑 3–5 首明亮的大调曲子给用户选（选曲规则见 method.md 第 6 节），路径写进 `plan.json` 的 `bgm`；嫌配乐小改 `bgm_lu`（12 更响、16 更轻）。
2. `python3 scripts/sfx.py <工程>`（补齐音效；没有 ElevenLabs key 自动用 Mixkit 免费音效）→ `python3 scripts/mix.py <工程>`。
3. 渲染前用 `npx --yes hyperframes@<版本> preview` 开预览，告诉用户可以在浏览器里看、拖时间轴。
4. `python3 scripts/render.py <工程> --name 口播_v1 --open`。
5. 用户要在剪映里手改时：`python3 scripts/export.py <工程> --name 口播_v1` → `交接/`（字幕.srt、图层.mov、分开的素材、剪映草稿）。草稿打不开就用前三样手动拼。

### Step 6 听审、核实、修改

1. 问用户能不能把成片发给 Gemini 审（用户自己的 Google 账号）。同意后：`python3 scripts/review.py <工程> --video 成片/口播_v1.mp4`，读 `审片意见.md`。
2. **逐条核实**（references/review.md）：卡顿、残音用 `probe.py --say` / `--near` 回原片听写；音效太冲看 `work/sfx_events.json` 那一秒有什么。属实的改，误报的标出来。
3. 改完出 v2，把「用户说的 + 审片查到的 + 改法」写进工程的 README.md。
4. `python3 scripts/dei_workspace.py log dei-talking-head "<主题>口播" ok <成片路径>` 记一笔。

### 省时间（一条 1 分钟口播，机器时间应在 3 分钟内）

用户反馈「剪辑的时长实在是过长」：第一次在 WorkBuddy 里剪 45 秒的片子用了 24 分钟，机器只占一小半，大头是 cut.py 跑 4 遍、build.py 跑 4 遍、每遍之间读图想改法。照下面做：

- `cut.py` 迭代时加 `--no-verify`，删改定了最后跑一次带核对的。macOS 自动用硬件编码，一遍约 20 秒。
- 一次写完 `画面方案.md` 和 `scenes.py` 再 build；用 `--snap auto` 一次看全每段画面，**最多改 2 轮**，剩下的小问题列给用户。
- 等用户确认删改清单时，同时挑好配乐候选；`sfx.py` 在第一次 build 之后马上跑。
- 不在 /tmp 自己搭测试、不去读生成的 HTML 查 GSAP；报错看 build.py 的提示。
- 不开 preview，除非用户要在浏览器里拖时间轴。

### 改版

用户看片的意见按「改哪里」处理：刀口卡、吞字 → `plan.json` 的 keep / cut / no_split，重跑 cut.py（`scenes.py` 里写死的秒数会自动跟着挪）；画面 → `scenes.py`；音效太冲 → `plan.json` 的 `sfx_levels` 或换音效；配乐 → `bgm` / `bgm_lu`；节奏 → `speed`。用户反馈里有新的通用规则，补进 method.md 对应的节。

## 缺少信息时

- 没有 ElevenLabs key：`sfx.py` 自动用 Mixkit 免费可商用音效（运行时下载，不需要账号）；也可以把用户自己的可商用音效同名 wav 放进 `work/sfx/`。
- 没有 `agy`：跳过 Step 6 的模型听审，请用户戴耳机逐刀听，重点听刀口核对里列出的位置。
- 没配字体：先用系统字体出一版，告诉用户推荐的免费商用字体。

## 边界与停止条件

- 删改会改变原意、拿不准的：停下列给用户，不自己决定。
- HyperFrames 检查报错：先改，不带错误渲染；渲染失败两次就停下，把错误给用户。
- 网站下载遇到人机验证、登录墙：给链接请用户自己下载。

## 输出

```text
<工程>/
├── plan.json  scenes.py          剪什么、画什么（改版只改这两个）
├── 画面方案.md                    每段选什么版式、为什么（写 scenes.py 之前）
├── 逐字稿.md  删改清单.md  刀口核对.md  审片意见.md
├── source/原片.*                  不动
├── work/                          edl、字幕、音效、转写等中间文件
├── hf/                            HyperFrames 工程（build.py 生成，不手改）
├── 交接/                           字幕.srt、图层.mov、素材/、剪映草稿/（export.py）
└── 成片/口播_vN.mp4               1080×1920，-14 LUFS
```

交付时说明：成片在哪、删了哪些（附理由）、用的配乐和音效来源、听审查出了什么、哪些地方还要用户自己听一遍。

## 禁止事项

- 不改动原片，不删旧版成片。
- 不把用户的出镜视频未经同意上传给第三方模型或网站。
- 不把 ElevenLabs key、Google 账号信息写进工程、日志或回复。
- 不用来源不明、只限学习交流的音乐、音效、字体做成品。

完成当前任务后直接结束。用户的请求超出本 Skill 范围，或询问下一步时，用一句话说明还需要哪种能力，不点名其他 Skill；当前环境已经安装 `dei` 时，补一句「可以用 `$dei` 继续」。

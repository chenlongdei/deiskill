# 口播剪辑的方法

来源：一条 3 分钟的知识口播（「我离不开的 2 个 AI 工具」），从 v1 到 v6c 剪了 9 版：先是只删口误、3:4 留黑、苹果风卡片，后来按市场打法重剪。下面每一条都来自用户看片后的真实反馈或核实过的问题。

## 0. 录的时候就给 AI 留好刀口

- **说错了，停 2 秒，从这句话开头重说。** 别从半句接着说：AI 找「同一句说了两遍」很准，找「半句接半句」容易剪坏。
- 要演示动作、等页面加载的地方，嘴上说一句「大家看这里」，不然这段安静会被当停顿剪掉。
- 录完原片复制一份放好，原片永远不让 AI 动。

## 1. 思路：不绑工具，绑交接件

和工作盘「本地文件夹是唯一的源头，每个工具只占一格」是同一个道理。工具会换，交接件不换；每一步只要读得进上一份、交得出下一份，用什么工具都行。好处：换工具只换一格；每一步都有文件留底，哪一刀剪错了能查回去、能撤回。指挥是智能体（Claude Code、Codex、WorkBuddy 都行）。

| 交接件 | 是什么 | 谁产出 → 谁用 |
| --- | --- | --- |
| `source/原片.*` | 原始素材，只读 | 用户 → 所有步骤 |
| `逐字稿.md`、`work/src_tr.json` | 每句话 + 原片秒数 | 转写 → 删改判断 |
| `plan.json` → `删改清单.md` | 保留 / 删掉哪几段、为什么 | Agent 写 → 用户审 → 剪 |
| `hf/assets/aroll.mp4`、`voice.wav` | 剪好、提速、处理过的画面和人声 | 剪 → 画面、混音 |
| `work/captions.json` | 对好新时间的字幕 | 转写 → 画面 |
| `hf/`、`成片/` | 可改的工程和成片 | 画面 → 用户 |
| `交接/字幕.srt` | 对好成片时间的字幕 | 转写 → 剪映 |
| `交接/图层.mov` | 透明背景的图解、贴纸、标题层 | 画面 → 剪映 |
| `交接/剪映草稿/` | 多轨工程：人物、空镜、图层、字幕、人声、配乐、音效分轨 | 合成 → 用户手改 |

每一步的首选和替补：

| 步骤 | 首选（本 Skill 用的） | 为什么 | 替补（什么时候换） |
| --- | --- | --- | --- |
| 0 录 | 说错停 2 秒、从句首重说 | 后面每一步都省事，零成本 | — |
| 1 转写 | whisper.cpp + large-v3-turbo（`new.py`） | 本地、免费、中文准，3 分钟只错 2 个专有名词 | 录音嘈杂、口音重 → ElevenLabs Scribe（上传、收费）；只想省事 → 剪映识别字幕 |
| 2 删停顿 | ffmpeg 静音检测（`cut.py`） | 刀口精确，参数可调 | 不想碰命令行 → 剪映自带去停顿 |
| 3 删口误重录 | Agent 读稿列清单 → 用户审 → ffmpeg 剪 | Agent 读得懂整段意思，能分清「然后」有没有用；每刀有记录 | 长录像要边看边拖 → ChatCut 时间线；剪映文本剪辑 |
| 4 字幕 | 剪完重新转写 + jieba 分词断句 | 时间准，不会断成「找不 / 到」 | 剪映识别字幕（改了剪辑要重来） |
| 5 图解 | HyperFrames（`build.py` + `scenes.py`） | 图标、流程、对比、动画最灵活，免费，能照对标风格做 | 同一个样子要出很多条 → Remotion 做模板 |
| 6 空镜、配乐 | Mixkit + 自动闪避（`broll()`、`mix.py`） | 免费可商用免署名；音量精确到分贝 | Mixkit 找不到 → Pexels（要免费 key） |
| 6 音效 | ElevenLabs 生成（`sfx.py`） | 可商用、想要什么声音写一句话 | 自己的可商用音效库（同名 wav 放进 work/sfx/） |
| 7 人声 | ffmpeg 处理链（第 7 节） | 按频谱测出来调，同环境复用 | 底噪、回声太重 → Adobe Podcast 人声增强，或达芬奇人声分离 |
| 8 竖屏出片 | HyperFrames 渲染 + 两遍 loudnorm（`render.py`） | 位置精确，全本地 | — |
| 9 手改 | 剪映草稿（`export.py`） | 用户最熟，手拖最快 | 草稿打不开 → `人物.mp4` + `图层.mov` + `字幕.srt` 手动拼；要给 Premiere、达芬奇 → ChatCut 导 XML |
| 10 听审 | Gemini（Antigravity CLI `agy`，`review.py`） | 能听音频，抓卡顿和音效问题 | 用户自己戴耳机逐刀听 |

一句话：whisper 听写，ffmpeg 动剪刀，Agent 判断删哪句、用户拍板，HyperFrames 做画面，剪映收尾，Gemini 听审。

### 什么时候换一格

每过一阵（比如每月），拿同一条**标准测试口播**重跑一遍，看哪一格有更好的选手。测试口播 5–10 分钟，单人、原声清楚，故意放进：2–3 处长停顿和几处自然呼吸；独立的「嗯 / 呃」和有实义的「然后 / 其实」；同一句重录 2–3 遍，至少一次「错的一句 → 不对 → 对的一句」；5 个专有名词、数字和否定句；一段 20 秒的演示等待；一个绝不能删的结论。

| 看到这种情况 | 换哪一格 |
| --- | --- |
| 某个转写工具专有名词错得更少 | 第 1 步 |
| 剪映 / ChatCut 删口误，用户审清单时要改的处数更少 | 第 3 步 |
| 新的动画工具做同一张卡片更快、更好看 | 第 5 步 |
| 某个降噪工具处理前后对比明显更干净 | 第 7 步 |
| 某个模型听审误报更少、漏报更少 | 第 10 步 |

只看三个数：**删错几处、漏删几处、人自己花了多少分钟。** 不看谁宣传得好。

## 2. 删改：先给清单，用户拍板

- **AI 找，用户定。** 自动删停顿抓不到口误；口误和重录要 Agent 读整份稿找出来，每处写原片时间和理由，用户确认后再剪。
- 重录只留最后一遍完整说对的；「错的一句 → 不对 → 对的一句」，前两截一起删。
- 不删：结论、数字、否定词、有逻辑作用的「然后 / 其实」；演示、等待、卖关子的停顿（有人 4 分钟的跟练视频，30 秒动作保持被当停顿剪没了）。
- **市场版可以按内容重剪**：开头 10 秒里讲理论铺垫、讲「以后再介绍」这类不给信息的话，可以整段删。这一版删了 25 秒理论铺垫和两句空话，3:00 → 2:05。但这属于改内容，必须写进删改清单让用户确认。
- 字幕可以顺手去口癖（「在接下来呢」→「接下来」），声音不改。

## 3. 刀口：每一刀都要经得起听

- **刀口落在静音里。** 下刀前 `probe.py --near <秒>` 列出附近 0.06 秒以上的细静音，挑一个下刀。
- **被删的词不能留尾音。** 实例：删「当它是」时入点写在 129.25，「是」的尾音 0.1 秒留了下来，接在「所有的」前面，听着像「这…所有的」结巴。入点挪到 129.48（静音里）就好了。
- **留下的词不能被削尾巴。** 「软件」的「件」尾巴落在 128.01–128.08，说话段检测没包住；保留段写到 128.10，`cut.py` 会剪到这里（保留段两头和说话段差 0.15 秒以内时，以 plan.json 为准）。
- **句中短于 0.45 秒的停顿不切**（`split_gap`）。实例：「所有的笔记都是以 Markdown 的格式保存在你的电脑上的」被切成 0.5–1 秒的碎段，每段画面还推拉一次，用户一眼看出「卡了两三下」。
- 句与句之间收气口：每刀留 0.07 秒（`pad`）。
- **提速 1.1 倍**（音高不变），是抖音知识口播的常见语速。
- 每次剪完读 `刀口核对.md`：每个语义刀口前后 2.5 秒的转写。转写只能抓到吞字和多字，抓不到「一顿一顿」，所以还要第 9 节的听审。核对是在提速、处理过的人声上转写的，短窗口里 whisper 偶尔会漏字或冒出繁体；看到漏字先用 `probe.py a b c d` 在原片上复核，原片接起来是完整的就不用改。

## 4. 画面：市场版

用户说「不按原来的约束，按市场做到最好」之后定的打法（实现在 `scripts/build.py`，写法见 scenes.md）：

- **全屏人像**，跳切处 1.0 / 1.12 交替换景别遮跳切，两次至少隔 2 秒；开头 4.4 秒慢推。
- **常驻标题 + 进度条**：中途刷进来也知道在讲什么，标题写结果（「我离不开的 2 个 AI 工具」），数字用荧光绿。
- **大号粗字幕**：粗黑体 + 黑描边，关键词荧光绿，一行不超过 11 个字，按词断句，一组一组弹出。位置在下巴下面（y≈1130），始终在平台安全区里。
- **讲结构就切整屏图解，讲观点回人脸。** 这一版 9 段图解约 90 秒、人脸约 35 秒；用户觉得人脸少可以把图解改成画中画。
- **人像上的贴纸**放左侧一列（x≈170），避开脸和右侧按钮栏；不压眼睛。
- 配色墨黑 + 荧光绿（用户的品牌色，不用粉黑）。

用户以前用过的另一种：9:16 画布里放 3:4 画面、上下各留 240 像素纯黑给平台 UI，卡片在下巴以下。要这种风格时改 `build.py` 的主合成布局。

## 5. 图解怎么画

- **画结构，不复述口播。** v4 的卡片把口播原句提炼成文字再放一遍，用户说「只是在复述我说的话，没有信息增量」。改成图标、流向、对比、计数后被肯定。
- 文字只留三种：节点下面 2–4 个字的标签、左上角章节号、字幕。
- 一段只讲一件事；静止的卡片 8 秒就死了，长段要分步出（逐条、逐个节点）。
- **对比要具体、停得住、接力过渡。** 用户原话：「我不会让 Codex 那个图标消失那么快，可以做一个左右对比……很自然过渡过来，形成一个张力对比。」做法：两边同屏 + 中间 VS；上面是同一句输入（「帮我写一份周报」）；左边结果是一段灰色文字，右边是「周报.docx 已存到桌面 ✓」；说到结论时，同一张左卡挂上「聊天机器人」被红线划掉、变暗，同一张右卡亮起「AI Agent · 能动手」。
- 讲到某个产品时放它的官方 logo；图标用 IconPark（Apache-2.0，可商用）。阿里 iconfont 每个图标授权不同，不批量用。

## 6. 音效和配乐

- 每个画面动作配一个音效：图解进场 whoosh、弹出 pop、逐条 tap、结果 ding、划掉 strike、高亮 sparkle。
- **宁轻勿冲。** 实例：1 分钟左右「现在 ↓」的砸字音加上打字动画的三下重击，用户说「过于强烈，和打字声冲突」。砸字换 pop、三下重击换一段 2.8 秒的轻键盘声、砸字整体降 4 dB。
- 写字的摩擦声、吱吱声很廉价，不用。
- 配乐要明亮、大调；小调曲子被评「神秘、诡异、不贴主题」。先把曲子自身的响度起伏拉平（有的曲子前奏到后段差 8 dB），说话时比人声低约 25 dB，停顿只抬 2 dB，过渡约 1 秒。

## 7. 人声

用户以前在达芬奇里处理，现在用 ffmpeg 一条链（`cut.py` 的 `VOICE_CHAIN`，按频谱测出来的）：高通 75 Hz → 轻降噪 → 280 Hz -2.5 dB 去浑 → 3.8 kHz +4 dB 提清晰度 → 9 kHz +2.5 dB 空气感 → 去齿音 → 3:1 压缩 → 限幅。这条原声 2.5–8 kHz 比 320–640 Hz 低约 20 dB（偏闷），处理后说话音量起伏从 8.2 dB 降到 4.2 dB。换了麦克风或房间要重新测。

## 8. 响度

成片 -14 LUFS（两遍 loudnorm），峰值 -1.5 dBTP。

## 9. 剪完听审

见 review.md。一句话：Agent 看不到真实的声音，卡顿、音效太冲这类问题要能听音频的模型来抓，抓到的每一条回原片核实。

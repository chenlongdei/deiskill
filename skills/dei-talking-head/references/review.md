# 剪完听审：让能听音频的模型审片，逐条核实再改

## 为什么要这一步

Agent 看片只能抽帧看画面、把声音转成文字，**听不到真实的声音**。实例：一版成片里「1:22 卡了两三下」「1 分钟左右键盘音效太冲」都是用户自己听出来的，抽帧和转写都没发现。

Gemini 能直接看视频、听音频。实测（2026-11-23，Antigravity CLI，20 秒片段）：

- 它自己听出了 1:22–1:28 的卡顿（「一顿一顿、拼剪痕迹」），时间点对得上；
- 它还指出那一刀有「这…所有的」的结巴感。回原片核实：删掉的「当它是」，「是」的尾音留了 0.1 秒——这是 Agent 没发现、用户也没说出来的问题；
- 它也会误报：片段开头结尾的「截断」「残音」是切片造成的；
- 20 秒片段约 1.5 分钟出结果；第一次跑时 5 分钟超时没出字，放宽到 15 分钟才出。

结论：**剪完之后**听审有用；剪之前让它出建议价值不大（删哪句、怎么排，读逐字稿就能判断）。它更适合拆对标视频的节奏和画面。

## 怎么跑

1. 先问用户：成片会发给 Google（用户自己的账号）。出镜内容敏感的不审。
2. `python3 scripts/review.py <工程> --video 成片/口播_v1.mp4`：30 秒一段，前后各多 1 秒重叠，逐段审，结果写进 `审片意见.md`。只审一段用 `--range 75,95`。
3. 没有 `agy` 的：`config.json` 的 `reviewer_cli` 可以换成别的能看视频的命令行；都没有就请用户戴耳机，按 `刀口核对.md` 的时间逐刀听。

## 核实（每一条都要做）

| 它说 | 怎么核实 | 属实怎么改 |
| --- | --- | --- |
| 某处卡顿、一顿一顿 | 看 `work/edl.json` 那一秒附近是不是有几个很短的段（< 1 秒）；看推近是不是连着换了几次 | 把那句加进 `no_split`，或调大 `split_gap` |
| 吞字、尾字被吃 | `probe.py --near <原片秒数>` 找静音，`probe.py a b c d` 试不同出点 | 保留段结尾写到静音里 |
| 多出半个字、结巴 | `probe.py --say <原片秒数段>` 听被删那段的最后一个字到哪 | 入点挪进静音 |
| 音效太冲、打架 | 查 `work/sfx_events.json` 那一秒有哪些音效 | 换轻的音效、`sfx_levels` 降音量、删掉重叠的 |
| 字幕 / 图解挡住、看不清 | `build.py --snap <秒>` 截那一帧 | 改 `scenes.py` 位置 |
| 片段开头结尾截断 | 这是切片造成的 | 不改，标「误报」 |
| 转写也判断不了的（「听着结巴」「一顿一顿」，原片转写只有一遍） | 原片里说话人本来就停顿了的，多半是误报 | 标「待人工听」，把成片时间列给用户自己听，不自己猜着改 |

实测（Skill 版重做同一条口播后再审 1:20–1:35）：它报「所有的」说了两遍、「而」字重复。回原片：「而……基于」中间本来就有 0.6 秒停顿，只说了一遍「而」，判为误报；「所有的」原片转写只有一遍，转写判断不了，标「待人工听」。所以它的意见只能当线索，不能当结论。

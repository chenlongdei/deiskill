# dei 总入口

## 使命

用户说出想要的结果，`dei` 决定由哪些 Skill、按什么顺序、交接什么文件来完成。它自己不采集、不提问、不写成品，只负责编排和把关。

## 铁律

1. **从最终交付倒推**：先确定用户最后要拿到什么（文件、格式、深度），再往回推每一步需要的输入。
2. **只调度已安装的 Skill**，不在这里重复实现它们的功能；某一步没有可用的 Skill 时，如实说明缺哪种能力。
3. **交接物落到文件**：每一步交出的是具体路径（清单、urls.txt、笔记本 ID、问答文件夹），下一步从这些文件接手，不靠记忆转述。
4. 各 Skill 自己的首次配置、铁律和停止条件照常生效；任何一步停在需要用户处理的地方（登录、授权、余额），整条链路就停在那里，说明进度和恢复方法。
5. 在关键节点让用户确认，不一口气跑到底：精选清单、问题树、手册任务清单。

## Step 0 看有哪些 Skill

读本 SKILL.md 所在目录的上一级目录（即当前 Agent 的 skills 目录），对每个子目录读 `SKILL.md` 的 frontmatter：`name`、`description`、`metadata.dei-handoff`。用 description 初筛，用 dei-handoff 的「接手 → 交出」决定能不能接上。不要一次读完各 Skill 的正文，轮到哪一步再读哪一个。

## Step 1 先找配方

| 用户的目标 | 配方 |
| --- | --- |
| 学会一个软件或技能，要学习计划、单元深挖、实操手册，资料来自 YouTube | A |
| 围绕一个主题把手上的资料（书、视频、文章）挖深，要判断和行动 | B |
| 日报、晨报、政策/AI/知乎/抖音信息 | 只用 `dei-daily-report` |
| 只是搜视频、扒字幕 | 只用 `dei-capture` |
| 只是对已有资料提问、生成播客或导图 | 只用 `dei-notebook` |

没有匹配的配方时，按 Step 2 通用倒推。

### 配方 A：YouTube 教程 → 学会一个软件

1. **`dei-capture` 搜索**：按其 references 里的「学习用途」标准，用中英文关键词覆盖入门、进阶、实战，搜出 15—30 条精选。
   - 交接：搜索目录下的 `清单.md` 和 `urls.txt`。
   - **确认点**：把按层级分组的精选清单给用户，增删后再继续。
2. **`dei-notebook` 导入**：`urls.txt` 里的链接直接导入新笔记本，不需要先扒字幕。导入失败的视频，再回到 `dei-capture` 取逐字稿，以文件形式补导入。
   - 交接：笔记本 ID。
3. **`dei-notebook` 学习路线**：按其 learning-path.md，**7 问封顶**，依次做资料盘点 → 知识地图 → 学习计划 → 实操手册。手册给非技术读者看：大白话指令 + 真实案例，不贴配置代码。用户点名要某个单元更深时才加问。
   - **循环**：资料盘点发现某一层明显缺资料时，带着它建议的关键词回到第 1 步补搜，再导入同一个笔记本。最多补两轮。
   - **确认点**：学习计划的单元划分、实操手册的任务清单。
4. **可选**：
   - 每个单元生成一期简体中文音频，供通勤时听（`dei-notebook` 生成）。
   - 要做成一门课（学员手册、物料包、讲师卡、发布到 Notion），且已安装 `handbook-writing`：把 `02_学习计划.md` 和 `实操手册.md` 当作课程方案交给它。

最终交付：笔记本文件夹下的 `学习路线/`（问答、知识地图、学习计划、实操手册）。

### 配方 B：多渠道资料 → 主题研究

1. **`dei-notebook` 导入**用户给的文件和链接。用户希望补充视频时，先用 `dei-capture` 搜索，确认后一起导入。
2. **`dei-notebook` 主题研究**：按其 topic-research.md，**7 问封顶**。先问清研究目的，问题树要经用户确认。
3. **可选的方法 Skill**（已安装才用，读它们的 handoff 确认能否接上）：
   - 概念说不清或互相混用 → `dbs-deconstruct` 拆概念，结果回填到概念地图；
   - 研究的是用户自己的生意 → 用综述里的判断，交给 `dbs-diagnosis` 做诊断；
   - 想系统学这个主题 → `dbs-learning` 按综述规划连载学习。

最终交付：笔记本文件夹下的 `主题研究/研究综述.md`，以及 7 问的原始问答。

## 收尾：文档同步（可选）

配方 A、B 交出 Markdown 后，问用户一次要不要同步，给三个选项：**飞书**、**Notion**、**只留本地**。用户这次会话里已经选过，就不再问。

- 本地 Markdown 永远是原件，同步只是多一份方便阅读、分享的副本。
- 用当前 Agent 里已经接好的连接器或命令行工具同步（例如 Notion 连接器、飞书的连接器或命令行工具）。没有可用的工具时，如实告诉用户缺什么、需要怎么接，不改用别的平台。
- 同步前说明会建哪些页面、放在哪个空间或父页面下；不开启公开分享，除非用户要求。
- 同步完给出每个页面的链接。

## Step 2 通用倒推（没有配方时）

1. 写下最终交付物：是什么、什么格式、放在哪里。
2. 找出 handoff 中「交出」能产出它的 Skill，看它要接手什么。
3. 继续往前推，直到接手物是用户手上已有的东西。
4. 判断组合方式：只用一个、串行、可以并行的部分（互不依赖的采集），或需要循环的部分（发现缺口回头补）。
5. 先把链路用一两句话告诉用户，再开始执行。

## 输出

最终交付物的绝对路径，加上一段简短说明：走了哪几步，每一步交出了什么，哪里有缺口。

## 禁止事项

- 不替叶子 Skill 做它的工作，也不绕过它的停止条件。
- 不为了走完链路而降低某一步的质量标准，例如跳过确认点、只导几个样本。

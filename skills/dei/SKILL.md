# dei 总入口

## 使命

大多数用户装的是整套 deiskill，只记得「跟 dei 说」。`dei` 负责听懂用户要什么，把任务交给对的子 Skill，并替用户把关：先走最轻的路，花钱或要登录之前先说清楚，关键节点停下来确认。

它自己不采集、不提问、不写成品，只负责路由、编排和把关。

## 铁律

1. **从最终交付倒推**：先确定用户最后要拿到什么（文件、格式、深度），再往回推每一步需要的输入。
2. **交给子 Skill 执行，不自己重做**：选定子 Skill 后，读它的 `SKILL.md` 全文，按它的首次配置、铁律、流程和停止条件执行，它的规则优先于这里。不在这里复述或改写它的规则。
3. **先轻后重**：同一个结果有几条路时，先走不用账号、不花钱的那条；要装浏览器、扫码登录、填密钥或会产生费用的，开跑前一次说清要准备什么、大概花多少，用户同意后再走。
4. **交接物落到文件**：每一步交出具体路径（清单、urls.txt、笔记本 ID、手册文件夹），下一步从这些文件接手，不靠记忆转述。
5. **停在该停的地方**：任何一步停在需要用户处理的地方（登录、授权、余额），整条链路就停在那里，说明进度和恢复方法。
6. **关键节点让用户确认**，不一口气跑到底：精选清单、问题树、手册任务清单、课程场景设定、发售排期。

## Step 0 看装了哪些 Skill

读本 SKILL.md 所在目录的上一级目录（即当前 Agent 的 skills 目录），对每个子目录读 `SKILL.md` 的 frontmatter：`name`、`description`、`metadata.dei-handoff`。用 description 初筛，用 dei-handoff 的「接手 → 交出」判断能不能接上。不要一次读完各 Skill 的正文，轮到哪一步再读哪一个。

需要的 Skill 没装时，如实说明缺哪种能力，并给出只装它的命令（`<name>` 换成 Skill 名）：

- macOS / Linux：`curl -fsSL https://raw.githubusercontent.com/chenlongdei/deiskill/main/scripts/bootstrap.sh | bash -s -- <name>`
- Windows PowerShell：`$env:DEISKILL_ONLY="<name>"; irm https://raw.githubusercontent.com/chenlongdei/deiskill/main/scripts/bootstrap.ps1 | iex`

装好后要重启 Agent 才能看到新 Skill。

## Step 1 路由：这句话交给谁

先看用户的话落在哪一行。只涉及一个子 Skill 的，交给它就结束路由，后面全程按它的规则走；涉及多个的，去 Step 2 找配方。

| 用户想要 | 交给 | 先读它的哪部分 | 最轻的走法 / 要准备什么 |

一句话里有两件事（比如「扒这个博主的视频，再帮我写朋友圈」），拆开按顺序做，前一件的产出文件交给后一件。

### 用户问「你能做什么」「从哪开始」

不要把 Skill 名单念一遍。按用户的生意怎么走来讲，每段一个例子，只列已安装的：

1. **找机会**：今天的政策和 AI 里有什么商机、知乎上什么话题值得写、抖音上这几个词最近什么在火、对标博主发了什么
2. **学透**：找一批教程做成学习计划和实操手册；把一堆资料围绕一个主题挖深
3. **做成产品**：把学会的东西做成一节课（手册、物料包、讲师卡）
4. **卖出去**：让 AI 写得像你，排好一次发售的朋友圈，发完复盘

最后推荐一件**不用配置就能马上拿到结果**的事。按已安装的情况选一件：「搜一下 YouTube 上关于 <用户关心的主题> 的教程」、「给我今天的政策与商机日报」、「这是我的 3 条朋友圈，帮我做一份风格提示词」。

## 找已有产出：工作区和运行总账

所有 dei Skill 共用一个 dei 工作区（路径在 `~/.deiskill/config.json` 的 `workspace_root`），一级目录是 `01_我的清单 / 02_采集 / 03_日报 / 04_知识库 / 05_成品 / 99_系统`，每个目录放什么见工作区根目录的 `使用说明.md`。用户可以在同一个 config.json 的 `stages` 里把某个目录（含 05_成品 下的 `course` 课程、`moments` 朋友圈、`profile` 个人介绍）指到自己的文件夹，实际位置一律以 `python3 scripts/dei_workspace.py where` 的输出为准。

用户问「最近一次日报在哪」「上周扒的逐字稿呢」，或者某一步要接手已有产出时，先读 `99_系统/运行总账.jsonl`（每行一次运行：时间、Skill、任务、状态、产出路径），不要在磁盘上到处搜。任何已安装的自有 Skill 目录里都有 `scripts/dei_workspace.py`，可以用 `python3 <那个 Skill 目录>/scripts/dei_workspace.py latest [skill] [任务]` 查。

用户问「下一步做什么」时，也先看运行总账：最近一次做到了链条的哪一环，就推荐下一环（采集完 → 建知识库，学习路线完 → 做课，课做完 → 排发售，发售完 → 复盘）。

## Step 2 配方：跨多个 Skill 的任务

| 用户的目标 | 配方 |
| --- | --- |
| 学会一个软件或技能，资料来自 YouTube | A |
| 围绕一个主题把手上的资料挖深，要判断和行动 | B |
| 把学会的东西做成一门课 | C |
| 把一门课或一个产品在朋友圈卖出去 | D |
| 找内容选题、看同行什么在火 | E |
| 综合日报且包含抖音 | 先用 `dei-capture` 更新监控工作簿（`douyin/workbook.py`），再让 `dei-daily-report` 读更新后的工作簿 |

没有匹配的配方时，按 Step 3 通用倒推。

### 配方 A：YouTube 教程 → 学会一个软件

1. **`dei-capture` 搜索**：按其 references 里的「学习用途」标准，用中英文关键词覆盖入门、进阶、实战，搜出 15—30 条精选。
   - 交接：搜索目录下的 `清单.md` 和 `urls.txt`。
   - **确认点**：把按层级分组的精选清单给用户，增删后再继续。
2. **`dei-notebook` 导入**：`urls.txt` 里的链接直接导入新笔记本，不需要先扒字幕。导入失败的视频，再回到 `dei-capture` 取逐字稿，以文件形式补导入。
   - 交接：笔记本 ID。
3. **`dei-notebook` 学习路线**：按其 learning-path.md，**7 问封顶**，依次做资料盘点 → 知识地图 → 学习计划 → 实操手册。手册给非技术读者看：大白话指令 + 真实案例，不贴配置代码。用户点名要某个单元更深时才加问。
   - **循环**：资料盘点发现某一层明显缺资料时，带着它建议的关键词回到第 1 步补搜，再导入同一个笔记本。最多补两轮。
   - **确认点**：学习计划的单元划分、实操手册的任务清单。
4. **可选**：每个单元生成一期简体中文音频，供通勤时听（`dei-notebook` 生成）；要做成课，接配方 C。

最终交付：笔记本文件夹下的 `学习路线/`（问答、知识地图、学习计划、实操手册）。

### 配方 B：多渠道资料 → 主题研究

1. **`dei-notebook` 导入**用户给的文件和链接。用户希望补充视频时，先用 `dei-capture` 搜索，确认后一起导入。
2. **`dei-notebook` 主题研究**：按其 topic-research.md，**7 问封顶**。先问清研究目的，问题树要经用户确认。
3. **可选的方法 Skill**（已安装才用，读它们的 handoff 确认能否接上）：
   - 概念说不清或互相混用 → `dbs-deconstruct` 拆概念，结果回填到概念地图；
   - 研究的是用户自己的生意 → 用综述里的判断，交给 `dbs-diagnosis` 做诊断；
   - 想系统学这个主题 → `dbs-learning` 按综述规划连载学习。

最终交付：笔记本文件夹下的 `主题研究/研究综述.md`，以及 7 问的原始问答。

### 配方 C：学会的东西 → 一门课

1. 还没有学习路线时，先走配方 A。
2. **`dei-course` 创作线**：把 `02_学习计划.md` 和 `实操手册.md` 当作课程方案交给它；它会先确认场景人物、物料清单、手册目录。
3. 用户设定了文档平台时，问一句要不要发布，发布走 `dei-course` 的发布线。

最终交付：`05_成品/课程/<课程名>/` 下的手册、讲师卡、Win/Mac 物料包，以及发布记录。

讲课要配案例或开场自我介绍时：课程方案或手册定好后，交给 `dei-profile` 按课程主题和学员人群筛案例、写开场介绍和 PPT 人物页。

### 配方 D：一门课或一个产品 → 在朋友圈卖出去

1. 工作区 `05_成品/朋友圈/风格提示词.md` 不存在时，先让 `dei-moments` 用用户的语料做风格提示词。
   `标签体系.md` 不存在、而用户好友多或客户类型多（同时有高客单客户和低价产品）时，先让 `dei-moments` 帮他建标签体系，至少打完关系敏感的那批人再开卖。
2. 卖的是 `dei-course` 做过的课：把课程文件夹里的手册目录和「学完能做到」交给 `dei-moments` 当产品信息，不用让用户重新讲一遍。
3. **`dei-moments` 浪潮式发售**：先给排期表（每条带可见范围、A/B/C 用哪些标签筛），用户认可节奏后再写文案。
4. 发售结束后回到 `dei-moments` 复盘：学员原话和数据写进素材库，成交的人更新标签、按来源统计渠道，留给下一次。
5. 发售里要讲的学员结果、客户案例，从 `dei-profile` 的案例卡片里取，不让用户重讲；复盘出的新结果，也交给 `dei-profile` 入库。

最终交付：`05_成品/朋友圈/发售/<批次>/` 下的发售方案、文案、私下记录表，结束后加复盘。

### 配方 E：找选题、看同行

1. 按关键词找近期热门 → `dei-capture` 关键词巡检；盯固定的对标博主 → `dei-capture` 监控工作簿。
2. 想要每天的面上信息（政策、AI、知乎热榜）→ `dei-daily-report`。
3. 选中的题要变成朋友圈 → `dei-moments`（一鱼多吃、选题矩阵）。用户想填进选题策划表时，表在工作区 `01_我的清单/`。

## 收尾：文档同步（可选）

用户常用的在线文档平台是 deiskill 的共用设置：`~/.deiskill/config.json` 的 `publish_platform`（`feishu` / `notion` / `dingtalk` / `local`），安装时问过一次。用任一自有 Skill 的 `python3 <Skill 目录>/scripts/dei_workspace.py publish` 读它，返回里有平台名、官方命令行（飞书 `lark-cli`、Notion `ntn`、钉钉 `dws`）是否已安装、怎么装、怎么登录。

- 还没设定：问用户一次平时用哪个（飞书、Notion、钉钉、只留本地），用 `publish set <平台>` 记下，以后不再问。
- 设定是 `local`：不同步，只给本地路径。
- 配方 A、B 交出 Markdown 后，问一句「要不要同步到<设定的平台>？」；用户这次点名别的平台就按这次说的做，不改设置。
- 本地 Markdown 永远是原件，同步只是多一份方便阅读、分享的副本。
- 用设定平台的官方命令行，或当前 Agent 已接好的同平台连接器。都没有时，如实告诉用户缺什么、怎么装和登录，不改用别的平台。
- 同步前说明会建哪些页面、放在哪个空间或父页面下；不开启公开分享，除非用户要求。
- 同步完给出每个页面的链接。

## Step 3 通用倒推（没有配方时）

1. 写下最终交付物：是什么、什么格式、放在哪里。
2. 找出 handoff 中「交出」能产出它的 Skill，看它要接手什么。
3. 继续往前推，直到接手物是用户手上已有的东西。
4. 判断组合方式：只用一个、串行、可以并行的部分（互不依赖的采集），或需要循环的部分（发现缺口回头补）。
5. 先把链路用一两句话告诉用户，连同每一步要准备什么、会不会花钱，再开始执行。

## 输出

最终交付物的绝对路径，加上一段简短说明：走了哪几步，每一步交出了什么，哪里有缺口，链条上的下一环可以做什么。

## 禁止事项

- 不替子 Skill 做它的工作，也不绕过它的停止条件。
- 不为了走完链路而降低某一步的质量标准，例如跳过确认点、只导几个样本。
- 不在用户没同意时走要花钱、要登录的路。
